# 代码复用整改

版本：v1.0 · 日期：2026-11-20 · 各项是否完成只记在[开发进度](06-开发进度.md)，本文不记状态。

2026-11-20 对全部代码（Rust 后端、`src/app`、`src/features` 与 `src/core`、构建脚本与测试脚手架）做了一次只读审查，目标是找出重复实现和没有用上的现成代码。本文记录三件事：已经改掉的五批（§2）、评估后不做的项及理由（§3）、今后写代码要守的复用约束（§4）。

行号是审查当天的，改动后会漂移；找代码以函数名为准。

## 1. 结论

- 没有发现应该换成现成依赖的手写代码。几处手写（base64、UTF-16 编码、`toWellFormed`、后行断言的替代）是旧版 WebKit 或 `encoding_rs` 不提供所致。
- 成对的文件（`find.ts`/`findText.ts`、`math.ts`/`renderMath.ts`、两个 `numericColumns.ts`、`syntaxRoles.ts`/`syntaxRoleNames.ts`）是为入口包和 worker 做的有意拆分，不是重复。
- 重复最集中的三处：Rust 以目录 fd 为锚的文件原语、两个窗口各一套的设置管线、设置页的颜色编辑器与控件。
- 有四处重复已经让两份代码行为不一致（D01–D04），属于缺陷。

## 3. 评估后不做的项

| 项 | 位置 | 不做的理由 |
| --- | --- | --- |
| “打开文件”序列 4 遍 | `useDocumentWorkspace.ts` | 四处取 busy 的时机不同；等待空闲的那行必须留在调用处，包进 async 函数会让同一时刻的两次打开都通过（试过后撤回） |
| 标签快照两份、等编辑器就绪的轮询三份、链接点击两份 | `useDocumentWorkspace.ts` | 逐处对照后各有不同：一份吞异常一份抛出；轮询的间隔与判定条件不同；答案里的 `#` 链接不跳转 |
| 设置的加载 | 两个窗口的 hook | 文档窗口加载后还要设窗口大小、报错并受浏览器预览限制，共同部分只剩一次 `invoke` |
| CSS 其余近似重复的规则块（输入框、分段控件、小表单控件、侧栏容器） | `styles.css` | 样式表是分层写的，后面的规则有意覆盖前面的；把相隔很远的规则并到一处会改变层叠顺序，且各组之间有高度 26 对 28、内边距 9 对 8 之类的细差 |
| 草稿模块里三份 `name`、`open_dir` | `drafts.rs` | 底层已共用 `fs/mod.rs` 的函数，剩下的是把错误码映射成各自语义的一两行 |
| `sha256_hex` 的一行别名、AlreadyExists 的映射、AI 请求的 Bearer 头 | 多个 Rust 文件 | 都是一行；Bearer 头两处的请求类型不同，合并要引入泛型 |
| 草稿与 AI 响应的有界读取 | `drafts.rs`、`ai.rs` | 读失败时的错误码是各自的（`CORRUPT_DRAFT`、`AI_NETWORK`），与 `read_at_most` 的 `IO_ERROR` 不同 |
| `bounded_file.rs`、`atomic_write.rs` 里各一处目录比对，`atomic_write.rs` 自己的列目录 | `fs/` | 前者并入 `still_at` 会改一个错误码；后者忽略错误并内联过滤，规则不同 |
| `sketch.ts`、`icons.ts` 里新建 SVG 元素的几处；`sketch.ts` 的两遍描线 | `diagrams/` | 各带条件分支，系数 0.75 与 0.7 不同，改了省不了几行 |
| `EditorAdapter.ts` 的守卫语句、`compatibility.ts` 取源码片段、`prompts.ts` 的代理对判断与图片引用遍历 | 同左 | 每处一行；`EditorAdapter.ts` 的守卫在输入法路径上，`prompts.ts` 保留全部定义，规则与别处不同 |
| 去 BOM、手写二分、内联 clamp | 多个文件 | 都是一行表达式，二分的边界各不相同 |
| AI 抽屉的错误码提取、五个名称输入小表单 | `aiAssistant.ts`、几个组件 | 兜底值不同且引用 hook 文件会成环；小表单各自的排版不同 |
| `install.sh` 的架构与版本检查 | `install.sh` | 先于 verify 给出更直接的报错，保留无害 |
| 三个 Swift 脚本的样板 | `scripts/*.swift` | 现在各是单文件编译，拆公共文件要改编译方式 |
| 非 macOS 的平行实现（约 150 行） | `fs/*`、`drafts.rs`、`documents.rs` | 不是重复：在 macOS 上不编译，其中几个函数是测试的对照读取器。删不删是产品决定，未动 |

## 4. 复用约束

写新代码前先查，查到就用；`CLAUDE.md` 的“Reuse”一节是同一套规则的摘要。

### 4.1 规则

1. **先找再写。** 新增任何小工具（转义、校验、哈希、路径、颜色、防抖、取文本）之前，先在下表列的位置和全库里搜同名或同义的函数。
2. **第二次出现就提取。** 同一段逻辑要写第二遍时，把它提成一个函数放到下表对应的位置，两处都调用它；不要复制后改两个字。
3. **差异做成参数。** 两处只差错误码、上限、延迟或类名时，把差异做成参数；不要为了差异保留两份。
4. **一个事实只声明一次。** 上限、扩展名、正则、文案、ID 列表只在一处声明，别处引用。TypeScript 与 Rust 必须各写一份的，要有测试比对两边。
5. **校验器成对存在时共用内核。** 宽的校验与严的校验并存时，严的调用宽的再加条件（如 `localHtmlImagePath` 调 `localAssetPath`）。
6. **放在依赖最少的一层。** 纯函数放 `src/core` 或无依赖的模块，使 worker 和应用外壳都能用；外壳会用到的模块不得引入编辑器、CodeMirror、PDF.js、Mermaid、KaTeX。挪动后跑 `npm run build`，由入口包预算和 worker 检查把关。
7. **合并不得悄悄改行为。** 合并前读完两份代码，把差异列出来；差异是缺陷就修并加回归测试，是有意的就保留并写进注释。
8. **界面控件用现成的。** 设置里的行、分段按钮、开关、色板、字体选择，对话框的外壳和焦点陷阱，侧栏的拖动条，都先用 `src/app/components/` 里已有的。
9. **测试脚手架放 `tests/helpers/`。** 第二个测试需要同一个桩或管线时就放进去。
10. **评审时查重。** 改动里出现新的工具函数、正则常量或数值上限时，评审要搜一遍是否已有。

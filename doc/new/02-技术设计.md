## 2. 总体架构

### 2.1 进程与边界

- **Rust 进程**（`src-tauri/src`）：窗口、原生菜单、全部磁盘访问、导出 PDF 与打印、AI 的网络请求。所有命令在 `lib.rs` 的 `generate_handler!` 注册。
- **WebView**（`src`）：界面与编辑。没有文件系统和网络插件权限，只能通过自定义命令（IPC）和 `mino-asset:` 协议取数据。
- **分析 worker**（`src/core/markdown/analysis.worker.ts`）：Markdown 分析、预览与导出渲染、字数统计、文本与源码文件的预览。
- **PDF.js worker**：只在打开 PDF 时启动。

前端的分工：

- `src/app/useDocumentWorkspace.ts` 是唯一的编排者，持有标签、会话、菜单处理和几乎全部 `invoke` / `listen`。`App.tsx` 只负责摆放 `src/app/components/`，组件用到的名字必须出现在这个 hook 最后的 `return` 里。
- 发起 IPC 的文件只有四个：`useDocumentWorkspace.ts`、`binary.ts`（二进制暂存）、`useSettingsWindow.ts`（设置窗口）、`settingsEffects.ts`（两种窗口共用的设置读写）。`src/features` 与 `src/core` 不导入 Tauri；AI 客户端通过注入的 `transport` 调用命令。
- React 不持有正文的受控副本。可视化模式下正文在编辑器事务里，源码模式下在 CodeMirror 里。

仓库根目录：`src/`（前端）、`src-tauri/`（Rust）、`tests/`、`scripts/`、`doc/`，以及 `build.sh`、`start.sh`、`clean.sh`、`install.sh`、`vite.config.ts`、`index.html`。`Markdown编辑器.md` 是原始需求文件，不修改。

## 3. 状态与数据

### 3.1 文档、会话与标签

- **`DocumentState`**（`useDocumentWorkspace.ts`）：打开结果（`token`、`name`、`markdown`、`revision`、`assetKey`、`kind`、`encoding`、`size`）加上 `id`、`draftId`、`mode`（`visual` / `source-protected`）、图片地址表 `imageUrls`、待保存图片 `pendingFiles`、草稿恢复出的图片 `recoveredAssets`、`deferredVisual`（大文档尚未分析）等。文本、源码、PDF 的 `mode` 恒为 `source-protected`，用 `kind` 区分。
- **`DocumentSession`**（`session.ts`，纯状态机）：`generation`、`revision`、`savedRevision`、`persistence`（`idle` / `saving` / `failed` / `conflict`）、`diskRevision`、`errorCode`。
  - `dirty = revision !== savedRevision`。载入、分析、切换风格不推进 `revision`。
  - `beginSave` 发出票据 `{ generation, revision, diskRevision }`。结果回来时 `generation` 不同则丢弃；保存期间又有编辑时只把 `savedRevision` 推进到票据的 `revision`，文档仍为未保存。
  - `discardChanges` 用于文件被移到废纸篓；`withGeneration` 用于同一文档换一种模式重新显示。
- **标签**：`TabItem = { key, document, session }`，每个窗口各有一组。切换标签时编辑器实例留在 `editorPool`（最多 5 个，最久未用的先释放，关闭标签立即释放），撤销历史、选区和滚动位置因此保留。
- **窗口**：文档窗口的标签为 `main` 或 `workspace-<n>`，各自持有标签与文件栏。标签拖出或“移到新窗口”时，正文、会话与待保存图片放进 `TransferStore`，新窗口用 `take_window_transfer` 领取；文件授权不撤销。
- **外部变化**：没有文件监听。前端每 3 秒调用 `check_document_revision`，返回 `same`、`changed` 或 `deleted`；Rust 先比较文件的修改时间、长度、inode，未变不重新哈希。无未保存修改时自动重载，有修改时进入冲突流程。

### 3.2 应用数据目录

位于 `~/Library/Application Support/app.mino.markdown/`。记录文件都经 `fs/app_data.rs` 读写：读取有大小上限且不跟随链接，写入用 `replace_record`（原子提交，旁边只留最新一份备份）。文件缺失、损坏或超限时按默认值处理，不报错。

| 文件 | 内容 | 上限 |
| --- | --- | --- |
| `settings.json` | 设置记录（3.3） | 64 KiB |
| `recent.json` | 最近打开的文件与文件夹：路径、类型、时间；最多 20 条 | 64 KiB |
| `session.json` | `main` 窗口上次打开的标签路径与当前标签；最多 20 个 | 256 KiB |
| `reading-positions.json` | 文本、源码、PDF 的阅读位置：键为路径的 SHA-256，值为页码（文本为 0）、0–1 的比例、时间；最多 500 条 | 256 KiB |
| `ai.json` | AI 配置（第 10 节），不含密钥 | 16 KiB |
| `drafts/<draftId>/snapshot-<序号>/` | 草稿快照：`manifest.json`、`document.md`、`assets/` | 清单 64 KiB |

- **草稿**（`drafts.rs`）：未保存的修改在停止输入 1.5 秒后写入，最迟 10 秒（`draftScheduler.ts`），输入法组词期间推迟。每次写一个新快照目录，未变的图片从上一个快照硬链接；每份草稿保留最近 3 个快照。清单记录 `draftId`、文件名、目标路径、`baseDiskRevision`、正文哈希与图片清单。列出草稿时给出目标状态：`same`、`changed`、`deleted`、`unknown`、`untitled`。草稿只经“文件 > 恢复草稿…”读取，启动时不自动恢复。
- **最近打开**：`recent.rs` 同时调用 `NSDocumentController` 登记系统最近文档。菜单项的 ID 为 `recent:<类型>:<id>`，`id` 是路径哈希的前 24 位，不含路径；选中后由 `choose_recent_file` / `choose_recent_workspace` 重新校验路径再授权。
- **会话恢复**：`remember_session` 与 `restore_session` 只接受 `main` 窗口，前端只传令牌。恢复时跳过已不存在的文件并报告数量。打开的文件夹不随会话恢复。
- **阅读位置**：只有持有有效文档令牌才能读写；文件或文件夹在应用内改名、移动后，键随之改写。Markdown 的位置只在本次运行内记住。

- **迁移先于校验**（`migrate`）：旧风格 ID 按 `LEGACY_STYLE_IDS` 改写；`cjkFont` 的 `huosong` 改为 `song`、`hei` 改为 `sans`；旧的 `fontPreset` / `editorFont` 换算成 `cjkFont` / `latinFont`。迁移后的值在下次写入时落盘。
- **整份不合法时逐字段回退**（`field_by_field`）：合法的字段保留，不合法的各自取默认值，不因一个字段丢掉整份设置。
- **缺失字段的默认值**保持旧版本的观感，与新安装的默认值（`Settings::default()`）不完全相同。例如字号：缺失时为 15，新安装为 16；`⌘0` 还原到 15（`textZoom.ts`）。
- **写入只接受补丁**：`update_settings { patch }` 只合并出现的字段，未知字段或 `schemaVersion` 返回 `INVALID_SETTINGS`。一个窗口因此不会把另一个窗口的旧值写回去。前端由 `settingsPatch` 比较引用得出补丁，所以对象类型的设置每次修改都换新对象，不就地改。
- 进入 CSS 的值在两侧都校验：风格 ID、字体族名（`is_system_family_name` 拒绝控制字符与引号、反斜杠、逗号、分号、花括号、尖括号）、颜色只收 `#rrggbb`、角色只收已知名字。

## 4. IPC 与错误码

### 4.1 命令的约定

- 命令在所属模块里实现，在 `lib.rs` 的 `generate_handler!` 注册，由第 2.1 节列出的四个文件调用。
- 读写文件、计算哈希、解码图片的命令用 `#[tauri::command(async)]`，不占主线程；需要等待对话框或长时间运行的（保存面板、导出、`ai_chat`）是 `async fn`，其中导出与 AI 进一步放到阻塞线程池。改动原生菜单必须回到主线程（`run_on_main_thread`）。

## 5. 文档管线

### 5.1 分析与模式

`prepareMarkdown`（`codec.ts`）调用 `analyzeMarkdown`（`compatibility.ts`），得出 `mode`、问题列表与保存时要还原的记录。下列任一情况为 `source-protected`：

| 问题码 | 情况 |
| --- | --- |
| `VISUAL_SIZE_LIMIT` | UTF-8 编码超过 2 MiB |
| `INVALID_UTF8`、`MIXED_NEWLINES`、`UNCLOSED_FRONT_MATTER` | 字节不是合法 UTF-8；换行混用或有单独的 CR；front matter 没有结束行 |
| `UNSUPPORTED_NODE`、`UNKNOWN_EXTENSION` | 出现支持清单之外的节点；指令语法、其他编辑器的扩展写法、单波浪线删除线、编辑器会改写的公式写法 |
| `ROUNDTRIP_RISK` | `latex` 代码围栏（Crepe 会把它存成公式） |
| `PARSE_FAILED`、`SERIALIZE_FAILED`、`SEMANTIC_CHANGE` 及各 `…_CHANGE` | 解析或序列化失败；解析 → 序列化 → 再解析后语义、front matter、BOM、换行或末尾换行发生变化 |

规范写法的公式（`$x$` 与成对的 `$$`）、原始 HTML、脚注留在可视化模式。原始 HTML 与脚注记为 `fragments`，编辑器载入后在 worker 里再核对一次是否原样返回，不符则退回源码保护。

- **可视化**：正文交给 `EditorAdapter`。编辑器事务是正文的唯一来源；自定义的输入处理在输入法组词期间不执行。
- **源码保护**：阅读时显示净化后的预览（`renderMarkdownPreview`），编辑时用 `SourceEditor`，保存的就是源码本身，不经过序列化。导出照常可用。

### 5.2 字节保真

- 分析时记录 front matter、BOM、换行风格（LF / CRLF）、末尾是否有换行；`composeVisualMarkdown` 保存时原样拼回。这一对函数必须同步修改，`tests/markdown-fidelity.test.ts`、`tests/markdown-codec.test.ts`、`tests/visual-roundtrip.test.ts` 检查。
- 没有修改的文档不写盘。`revision` 是磁盘字节的 SHA-256，与编码无关。
- `SourceEditor` 设置了行分隔符，单一换行风格的文件按行编辑，混合换行的文件把每个 `\r` 当作字符保留（`sourceText.ts`）。

### 5.3 大文档

不少于 200,000 字符且以阅读模式打开的 Markdown 文件不做分析、不加载编辑器：先用预览渲染开头约 48,000 字符（在代码围栏外的标题或空行处截断），整篇渲染完成后替换。此时文档以 `quickReadAnalysis` 的占位结果持有（源码保护、内容不变），`deferredVisual` 为真。用户开始编辑时才运行真正的分析并加载编辑器，阅读位置按比例带过去；分析结果要求源码保护时留在源码模式。

### 5.4 分析 worker

`analysis.worker.ts` 处理的任务：`prepare`、`hydrate`、`rewrite-images`、`preview`、`export`、`image-urls`、`html-image-files`、`mermaid-sources`、`word-count`、`text-preview`、`code-preview`。

- 主线程通过 `analysisClient.ts` 的 `…Async` 函数调用。单个任务 120 秒未答复时终止并重建 worker，其余任务重发；worker 无法启动时在主线程执行。失败的任务不在主线程重跑。
- KaTeX 与代码语法包只在文档需要时由 worker 动态导入（`loadMathRenderer`、`loadCodeParsers`、`loadFileParser`）。
- 加载时访问 `document` 的模块会让 worker 无法启动，此时一切悄悄回退到主线程而不报错。`vite.config.ts` 为 `decode-named-character-reference` 配了别名并用 `workerWithoutDom` 检查产物；Vitest 发现不了这类问题。

## 6. 文件服务

### 6.1 路径授权

前端从不提供任意路径。路径只来自系统对话框、拖放、Finder 打开和已授权文件夹内的条目，由 Rust 的存储换成不透明令牌：

| 存储 | 令牌 | 授权内容 |
| --- | --- | --- |
| `DocumentStore` | `doc-<n>` | 一个文件：路径、`revision`、`asset_key`、文件戳、类型、编码 |
| `WorkspaceStore` | 条目令牌 | 一个文件夹根及其下的条目；每条记着所属的根 |
| `IntentStore` | `intent-<n>` | Finder、Dock 或拖入带来的路径，10 分钟内由目标窗口领取 |
| `SnapshotStore`、`StagingStore` | 快照 ID、`staged-<n>` | 内存中的导出快照与暂存字节 |

- 被选中的路径先规范化，最后一级是符号链接或不是普通文件的拒绝。同一文件夹重复打开返回原来的根令牌。
- 单文件授权只允许写文档自身和它旁边的 `assets/`；读图片限于文档父目录之下，相对路径最多 8 级，不含 `..`、反斜杠、冒号。
- 改名、移动、移到废纸篓在 `PATHS` 写锁内进行并同步改写文档授权（`relocating`、`removing`）；保存持有 `PATHS` 读锁。两者因此互斥，已打开的标签在文件移动后仍可保存。
- 文件栏不列出隐藏项和 `node_modules`、`target`、`dist`、`build`、`assets`、`venv`、`__pycache__`；搜索从已授权的根出发，跳过符号链接，不搜索 PDF，新搜索取消同一窗口的旧搜索。

### 6.2 以目录句柄为锚的操作（`fs/mod.rs`）

检查与使用之间路径可能被换成链接，所以文件操作先打开目录本身，再用 `*at` 系统调用在这个句柄之内操作，事后复查目录仍在原处。

| 函数 | 作用 |
| --- | --- |
| `open_directory`、`open_canonical_directory` | 以 `O_DIRECTORY \| O_NOFOLLOW` 打开目录；后者要求路径等于它的规范形式 |
| `open_file_at`、`open_directory_at` | `openat` + `O_NOFOLLOW` 打开目录内的条目 |
| `create_file_at` | `O_CREAT \| O_EXCL \| O_NOFOLLOW` 新建，名字被占用（含被链接占用）即失败 |
| `make_directory_at`、`ensure_directory_at` | `mkdirat` |
| `directory_entries`、`entry_c_name` | 列出目录；只接受单一的普通文件名 |
| `still_at`、`still_entry` | 复查路径或条目仍是手里这个句柄（dev 与 inode 相同） |
| `missing_or_refused` | 把打开失败分成 `NOT_FOUND` 与 `OUT_OF_SCOPE` |
| `write_chosen_file` | 导出专用，见第 9 节 |
| `sha256_hex`、`sha256_of_reader`、`hex` | 修订哈希；大文件分块计算 |

`fs/bounded_file.rs` 提供有上限的读取（`read_open`、`read_at_most`、`read_no_follow`、`read_canonical_parent`），读前读后各检查一次大小。

### 6.3 保存

`save_document` 的顺序：

1. 取走暂存的图片；检查正文不超过 20 MiB；有令牌时取 `PATHS` 读锁与授权，PDF 返回 `READ_ONLY`。没有令牌（首次保存）时先弹保存面板。
2. 按授权记录的编码把正文编码（`forceUtf8` 时改为 UTF-8）。编码失败在写任何图片之前返回。
3. 取全局 `SAVE_LOCK`。`expected_revision` 与授权不符返回 `STALE_OPERATION`；磁盘当前哈希与授权不符返回 `CONFLICT`。
4. 图片先写入 `assets/`（6.4），正文里的引用改成相对路径。
5. `atomic_write::commit` 提交正文；首次保存用 `commit_chosen`。
6. 更新授权，返回 `SaveResult`：新 `revision`、`asset_paths`、`kind`、`encoding`；`markdown` 只在图片引用被改写时才带回。

`atomic_write::commit`（macOS）的顺序，中间任何一步失败原文件都不变：

1. 规范化并打开父目录。
2. 读原文件并核对哈希（不符为 `CONFLICT`，只读为 `PERMISSION_DENIED`）。
3. 排他创建临时文件 `.mino-<文件名>-<pid>-<序号>.tmp`，复制权限、ACL 与扩展属性，写入并 `fsync`。
4. 再次核对原文件的哈希与 dev/inode。
5. 把原文件硬链接为 `.mino-backup-<文件名>-<哈希前 16 位>.bak`，再 `renameat` 覆盖。
6. `fsync` 目录并复查目录身份，失败为 `COMMIT_UNCERTAIN`。
7. 清理备份，只留刚被替换的那一份（`KEPT_BACKUPS = 1`）；清理失败不影响结果。

- 新建文件（没有 `expected`）用 `linkat` 落位，目标已存在返回 `TARGET_EXISTS`，不覆盖。
- 备份只认名字完全符合的普通文件；文件改名或移动时备份跟着改名（`move_backups`）。文件名过长时名字部分截短并加哈希。
- 故障注入（`Fault`：`Write`、`Flush`、`Replace`、`SwapParent`）只在 `#[cfg(test)]` 下，覆盖提交之前的失败。
- **冲突**：保存返回 `CONFLICT`，或轮询发现磁盘已变而标签有未保存修改时，会话进入 `conflict`，自动保存停止。前端用 `read_disk_version` 取磁盘版本做行级对比（`lineDiff.ts`），用户可以重载、覆盖或用 `save_conflict_copy` 另存一份。
- **自动保存**默认关闭。`autosaveDecision` 在未命名、无修改、已冲突时跳过，在保存中、输入法组词、编辑器未就绪时等待。
- **关闭与退出**：窗口关闭和菜单退出走同一流程，逐个标签保存或询问（`choose_unsaved_action`），失败或冲突则停止关闭。

### 6.4 图片与资源

- **显示**：本地图片的地址由 `hydrate` 改成 `mino-asset://localhost/<asset_key>/<相对路径>`。`asset_key` 是每个授权随机生成的 32 位十六进制数，无法从令牌推出。协议处理函数每次请求都重新查授权、限定窗口、限定为 PNG / JPEG / GIF / WebP / SVG，应答带 `nosniff` 与 `sandbox` 的 CSP。SVG 只能作为 `<img>` 显示，不能保存、导出或进入草稿。
- **粘贴与拖入**：图片先留在 `EditorAdapter` 的待保存表里，用 blob 地址显示。保存时经 `stage_binary` 上传，随 `save_document` 一起处理。
- **落盘**：`fs/asset_directory.rs` 以目录句柄打开文档旁的 `assets/`（没有则新建），校验格式与尺寸后排他写入 `image-<哈希前 24 位>.<扩展名>`；同名且内容相同则复用，内容不同则加 `-<n>`。删除正文里的图片不删磁盘文件。
- **随文档移动**：把单个 Markdown 文件移到别的文件夹时，它引用的 `assets/` 图片复制到目标（同名异内容返回 `ASSET_CONFLICT`，什么都不写）。原图只有在确认没有其他文档引用时才移到废纸篓：原文件夹里有打开的文档、任一 Markdown 或 HTML 文件的文本含该文件名、扫描超过 5,000 项或 256 MiB、原图已变，任一成立就保留。
- **另存**：`save_as_document` 把正文引用的图片一并写到新位置的 `assets/`，成功后才切换授权；失败时当前文档不变。

## 7. 其他格式

### 7.1 类型判定

`file_kinds.rs` 是受支持扩展名的唯一清单：`md`、`markdown` 为 `markdown`；`txt`、`text` 为 `text`；`pdf` 为 `pdf`；`CODE_EXTENSIONS` 里的约 50 个扩展名为 `code`。`src/features/document/kinds.ts` 重复这张表，`tauri.conf.json` 的 `fileAssociations` 向 Finder 登记同一组扩展名（角色均为 `Alternate`，不抢默认应用），`tests/document-kinds.test.ts` 比较三者。

扩展名只决定“当作什么打开”，内容还要复核：PDF 必须在前 1024 字节内出现 `%PDF-`；文本解码后不得含 NUL，其他控制字符不超过 0.5%。不符返回 `UNSUPPORTED_FORMAT`。新建接受除 `pdf` 外的受支持扩展名；重命名不能改变文档类型。

### 7.2 文本编码（`text_encoding.rs`）

识别顺序：UTF-8 BOM → UTF-16 BOM → 含 NUL 时按无 BOM 的 UTF-16 判断（判不出为 `UNSUPPORTED_FORMAT`）→ 合法 UTF-8 → `chardetng` 的猜测，再依次尝试 GB18030、Big5。GBK 按 GB18030 处理。每一步都要求严格解码成功，否则 `INVALID_ENCODING`。

- UTF-8 的 BOM 留在文本里，由 Markdown 的 codec 记录与还原；UTF-16 的 BOM 去掉后记在授权里。
- 打开时验证“解码再编码与原字节一致”（`exact`）。不一致的文件，或出现原编码写不出的字符时，保存返回 `UNENCODABLE`，用户同意后改存 UTF-8。绝不写有损的文件。
- 新建文件、另存为 Markdown、冲突副本以外的新文件一律 UTF-8。状态栏显示编码名。

### 7.3 纯文本与源码文件

- 这两类文档不进入 Crepe，不做 Markdown 分析；保存、草稿、冲突、自动保存沿用同一个会话状态机。只对 Markdown 有意义的路径（`switchToVisual`、导出快照、图片处理）以 `kind === 'markdown'` 为条件。
- **纯文本预览**（`textDocument.ts`）：字符全部转义，空行分段；识别“第…章 / 回 / 卷”、`Chapter N`、“序章”“后记”等章节行并输出为标题，大纲由此生成。输出只含 `p`、`h1`、`h2`、`br`、`section`。长文本每 80 段一个 `section`，用 `content-visibility: auto` 让屏幕外的部分不参与排版。20 万字符以上同样先显示开头。
- **源码预览**（`codeDocument.ts`）：按扩展名选语言，带行号，颜色与 Markdown 代码块相同；超过 500,000 字符不上色。HTML、XML 只作为文本显示。CSV、TSV 默认显示表格视图，可切回原文。
- 编辑用 `SourceEditor`，源码文件带语法高亮，纯文本没有。

### 7.4 PDF

- 只读。`kind` 为 `pdf`，永不为未保存；保存、另存、草稿、导出、打印、格式菜单、阅读与编辑切换都不可用（`native_menu::enabled_for` 置灰菜单，前端的 `runFileAction` 另行拒绝）。
- **字节来源**：PDF.js 通过自定义的分段传输调用 `read_document_range(token, offset, length)`。每次调用都重新取授权、确认类型、不跟随链接打开并核对文件戳，文件被替换返回 `CHANGED`。不整文件读入 WebView。
- **数据文件**：字符映射与标准字体由 `BinaryDataFactory` 经 `read_app_asset` 读取（只允许 `/pdfjs/cmaps/*.bcmap` 与 `/pdfjs/standard_fonts/*.pfb|*.ttf`）。`scripts/pdf-assets-plugin.mjs` 在构建时把它们复制到 `dist/pdfjs/`；`wasm/` 目录只放 JBIG2 与 JPEG 2000 解码器的 JavaScript 回退，不放 `.wasm`。
- **安全选项**：`useWasm: false`、`useWorkerFetch: false`、`enableXfa: false`、`disableAutoFetch`、`disableStream`，不执行文件里的脚本。外部链接经 `safeLinkHref` 与 `open_external` 打开。
- **视图**（`PdfView.tsx`）：所有页先占位，只渲染可见页及相邻页，离开视野的页释放画布并调用 `cleanup()`；单页画布 ≤ 1600 万像素；缩放 25%–400% 及适应宽度（尺寸变化 120 毫秒后才重画）。书签转为大纲（≤ 2,000 项）。查找在逐页提取并缓存的文字里进行。加密文件询问密码，密码只在内存中。
- 磁盘上的 PDF 变化后自动重新载入。

## 8. 阅读样式、字体、代码配色与图表

### 8.1 阅读风格

- 12 个风格是 `src/features/reading/styles.ts` 里的数据：`white`、`mist`、`paper`、`xuan`、`parchment`、`kraft`、`mint`（日间），`charcoal`、`dark`、`gray`、`slate`、`dusk`（夜间）。每条记录有纸色、正文与次要文字色、链接色、纹理、推荐字体、代码底色方案。有纹理的是 `paper`、`xuan`、`parchment`、`kraft`。
- `css.ts` 从这些数据生成编辑器、预览、HTML 导出和打印四处的 CSS，所以一种观感只改一处。`install.ts` 在启动时安装一次样式表。
- 切换风格、字体、纹理强度只改 `<html>` 上的 `data-theme` 与 CSS 变量，不重建编辑器，不产生文档修改。
- **界面色**：侧栏、标签栏、画布是中性灰与纸色按 `CHROME_TINT = 0.3` 混合，界面文字保持中性。窗口没有系统标题栏（`titleBarStyle: Overlay`），红绿灯在应用自己的顶行，空白处标 `data-tauri-drag-region`；窗口的明暗外观跟随风格（`setTheme`、`setBackgroundColor`），不跟随系统。全屏时去掉 `<html>` 的 `window-overlay` 类。
- `settings.rs` 重复风格 ID（`STYLE_IDS`）与旧 ID 映射（`LEGACY_STYLE_IDS`）。`tests/reading-styles.test.ts` 比较两边，并检查对比度：正文对纸色 7:1 以上，次要文字、链接、标题、代码 4.5:1 以上。

### 8.2 纸张纹理

`src/assets/paper/` 的 12 张 PNG（每种纸 3 层）由 `scripts/generate-paper-textures.mjs` 以固定种子生成，可逐字节复现；改脚本，不改图片。应用内按文件地址引用（`?url`，`textures.ts`），导出时经 `read_app_asset` 读入当前风格的各层并内联。`textureStrength` 只改变盖在纹理上的那层纸色的不透明度。

### 8.3 字体

- 选项在 `fonts.ts`：中文 7 款（`song`、`kai`、`sans`、`fangsong`、`zhengkai`、`xingshu`、`kaishu`），西文 5 款（`source-serif`、`literata`、`garamond`、`inter`、`mono`），代码 6 款（随包的 `jetbrains-mono`、`fira-code`、`source-code-pro`，系统的 `sf-mono`、`menlo`、`monaco`）。中文与西文分开选，字体栈西文在前、中文在后；`codeFont` 写入 `--code-font`，代码块、源码文件、源码编辑器共用。
- 随包 16 个字体族，族名都以 `Mino ` 开头。`scripts/generate-font-table.mjs` 生成两个文件：`bundledFonts.css`（应用启动时加载的 `@font-face`，`font-display: block`）与 `fontTable.ts`（同一批字体的数据，只有导出经 `fontFaces.ts` 读取，用来挑出文档用到的分片）。改动字体包后重新运行脚本。
- 来源：fontsource 的 npm 包，以及 `src/assets/fonts/chill-kai/`、`src/assets/fonts/zhuque-fangsong/` 两个整文件字体（各目录记有来源与许可）。只收许可允许再分发的字体，清单在 [licenses/](licenses/)。
- `sys:<族名>` 指本机字体，列表来自 `list_system_fonts`（只返回族名，不读字体文件）；族名在 TypeScript 与 Rust 两侧校验后才写进 CSS，并作为带引号的字符串输出。
- 以西文为主的文档（`script.ts` 的 `dominantScript`，不计代码、链接与 HTML 标签）通过同一批 CSS 变量得到西文版式；`latinLayout: off` 关闭。

### 8.4 代码配色

- 记号角色 14 个，在 `syntaxRoleNames.ts`（无依赖，可进入口包）。`syntaxRoles.ts` 把 CodeMirror 的标签映射到角色，编辑器（`codeTheme.ts`）、预览和导出共用这一份；预览与导出只输出 `tok-<角色>` 类名，颜色来自 `--syntax-<角色>`。
- 配色方案在 `codeColors.ts`，只设置 `--syntax-<角色>`，从不设置背景。`codePalette` 把每个颜色对风格的代码底色调到对比度 4.5（注释 3.2）以上，保持色相与饱和度只改明度。新增方案要给出日、夜两套。
- `custom` 是用户自己的颜色（`codeCustomColors`，日夜分开，只存改过的角色），按所选原样使用，不做对比度修正。
- `settings.rs` 重复方案 ID 与 `SYNTAX_ROLES`，`tests/code-colors.test.ts` 比较。

### 8.5 图表

Mermaid 图表的外观由三样决定：阅读风格、画法（`diagramStyle`）、画法之内的选项（配色方案或五个自定义颜色、标签字体、连线样式与走向、手绘画法的填充）。

| 画法 | 名称 | 成图方式（`DiagramPass`） |
| --- | --- | --- |
| `page` | 纸面 | `none`：只用 Mermaid 的变量与 CSS |
| `program` | 架构 | `cards`：`dress.ts` 的 `dressCards` |
| `hand`、`pencil`、`chalk`、`ink` | 彩笔、铅笔、粉笔、钢笔 | `sketch`：`sketch.ts` 的 `sketchDiagram` |
| `scifi` | 科幻 | `console`：`dressConsole` |
| `color` | 彩色 | `colors`：`dressColors` |

流程（`mermaid.ts`）：

1. `withIconPlaces` 把标签里确实是图标名的 `:name:` 换成私用区字符占位。
2. Mermaid 渲染。它始终画朴素的图：`securityLevel: 'strict'`、`htmlLabels: false`，主题变量与 CSS 来自 `looks.ts` 的 `diagramVariables` 与 `diagramConfig`。
3. `sanitizeDiagramSvg`（DOMPurify）净化。
4. `finished` 把 SVG 临时挂到文档里（要量尺寸和读计算样式），依次：居中批注文字、补画标签图标、按 `pass` 重画或装饰、`layBoard` 铺底板。

- **颜色**：`diagramTone(styleId, options)` 一次算出一张图的全部颜色，强调色经 `fitColor` 调到对底色对比度不低于 3。文档自己给节点指定了填充色的，一律不动。
- **手绘**（`sketch.ts`）：矩形、多边形、椭圆、直线和连线的轮廓由 `handOutline`、`handEllipse`、`handLine` 生成，边会弓起、摆动，角点会偏移；rough.js 只负责排线和任意形状的路径。随机数的种子由图形的位置决定，重画结果完全相同。连线首尾两点不动，箭头仍在线上。
- **图标与批注**（`icons.ts`）：图标取自随包的 Lucide 图标集（`@iconify-json/lucide`，懒加载，同时登记给 Mermaid 自己的图标节点）；云形、爆炸形、纯文字等节点是批注。
- **缓存与重画**：`diagramKey` 把风格 ID 与七项选项写成一个字符串，缓存（200 条）、元素上的 `data-diagram-key` 与 `restyleDiagrams` 都用它。风格或选项变化时只重画键不同的图，不重建编辑器。
- **宽度**：图表总是缩到所给宽度，页面与各种导出都不横向滚动。阅读模式下点击图表在 `ZoomViewer` 中按适合窗口打开；触控板捏合经 `pinchZoom.ts` 把倍数写到 CSS 变量 `--pinch-zoom`，不经过 React 状态，只在阅读模式生效。
- **字体**：两款手写字体（龙藏行书、马善政楷书）同时供图表与阅读使用；`fontReady` 以图表源码取样，只加载这张图用到的分片；导出按图表自己的文字内嵌分片。
- **入口包**：应用外壳只导入 `colorKey.ts`；`looks.ts` 与设置的“图表”页（`DiagramSettings.tsx`）按需加载。
- `settings.rs` 重复各选项的取值，`tests/diagram-looks.test.ts` 比较。画法的效果要在 WebKit 里核对，Chrome 对 SVG 滤镜和细线的渲染不同。

## 9. 导出与打印

### 9.1 快照

导出不读磁盘上的旧文件，也不截取应用的 DOM。前端捕获当前正文（等待输入法组词结束），找出图片引用，用 `create_snapshot` 建立不可变快照：待保存的图片来自暂存，磁盘上的图片由 Rust 按授权读入。快照带 `generation` 与 `revision`，之后切换文件或继续编辑不影响本次输出；用完由 `release_snapshot` 释放。

### 9.2 各种输出

| 菜单 ID | 做法 |
| --- | --- |
| `export-md`、`export-text` | `export_snapshot_md`：保存面板选位置，图片先写入目标旁的 `assets/`，再提交 `.md`；`text_only` 时只写正文 |
| `export-html` | worker 渲染（`renderExport`）→ `export_html` 写入所选文件 |
| `export-pdf` | 同一页面以 `pdf` 模式生成 → `export_pdf { html, title, paper, pageSize }` |
| `print`（`⌘P`） | 同一页面以 `print` 模式生成 → `print_page { html, title, pageSize }` |

- **导出页**（`renderHtml.ts`）：Markdown → 语法树 → 净化（`rehype-sanitize`）→ 代码高亮、图注、数字列、公式、已净化的图表 SVG → 完整页面。本地图片内嵌为 data URI，远程图片不抓取；页面带自己的 CSP：`default-src 'none'; img-src data:; style-src 'unsafe-inline'; font-src data:`（没有内嵌字体时为 `'none'`），没有脚本。
- **样式**（`exportStyle.ts` 的 `buildExportStyle`）：按文档用到的字符挑字体分片内嵌；超出预算时改用系统字体并提示。`exportStyle: plain` 用素色样式。本机字体不内嵌，只按族名引用。
- **PDF 与打印**（`pdf_export.rs`）：应用的 WebView 里 `window.print()` 不起作用，所以由 Rust 在主线程创建离屏的 `WKWebView`（关闭页面 JavaScript），载入页面，等字体与图片就绪后用 `NSPrintOperation` 打印。导出时直接打印到临时目录里的文件，不显示面板；打印时在文档窗口上弹出系统打印面板。纸张为 A4 或 Letter，AppKit 边距为 0，页边距由页面的 `@page` 决定。
- **整页底色**：WebKit 不绘制 `@page` 的页边距。导出的 PDF 先不带页面背景打印（`css.ts` 的 `pdfFile`），再用 PDFKit 在每页内容之下铺满纸色后另存，文字、字体和链接都保留。PDF 不带纸张纹理。打印按 `pdfMode`：`print` 为白底，`screen` 与屏幕一致。
- **线程**：不显示面板时 AppKit 可能在自己的线程回调，所以结果通道放在全局表里，不放在主线程的对象表里。
- **写入所选文件**：HTML 与 PDF 导出用 `fs::write_chosen_file`，原地写入保存面板选中的那一个文件（`O_NOFOLLOW`，不建临时文件，不留备份），在独立线程进行，30 秒未完成返回 `WRITE_BLOCKED`。不用 `atomic_write`，因为它要打开目标文件夹本身，而“下载”“桌面”等受隐私保护的文件夹不在保存面板的授权之内，`open` 会一直等待。

## 10. AI

- 默认关闭。`ai.rs` 是全应用唯一发出网络请求的代码；WebView 的 CSP 与权限不因 AI 改变，前端不得为它添加 `fetch`。
- **配置**：`ai.json`（`schemaVersion: 1`）记录是否启用、是否已同意、当前服务商、地址、模型，以及其他服务商各自记住的地址与模型。服务商为 `deepseek`、`openai`、`custom`，前两者有预置的地址和模型。文件缺失或不合法时按“未启用”处理。
- **地址**：必须是 `https`，只有回环主机（`127.0.0.1`、`localhost`、`[::1]`）允许 `http`；不允许带用户名、查询串或片段；长度 ≤ 300。`ai_chat` 不接受地址参数，地址只来自已校验的配置。
- **密钥**：按服务商存入 macOS 钥匙串，服务名 `app.mino.markdown.ai`，账户名为服务商 ID。密钥只在 `ai_set_key` 时由 WebView 传入一次，任何命令和事件都不返回它；配置视图只给出“是否已保存”。自动化测试用可替换的 `SecretStore`，不碰真实钥匙串。
- **同意**：首次启用要确认“文档内容会发送到所配置的服务”。请求将发往另一个源（换了服务商或地址）时，同意作废，需要重新确认。
- **检查顺序**（`check_access`、`run_chat`）：启用 → 同意 → 密钥（回环地址可以没有）→ 大小 → 并发，任一不通过都不发请求。AI 关闭或未同意时不读钥匙串。
- **请求**：OpenAI 兼容的 `POST <地址>/chat/completions`，流式；`ai_list_models` 为 `GET <地址>/models`，不带任何文档内容，最多 500 个模型、响应 ≤ 1 MiB。不跟随重定向，不读失败响应的正文，回环地址不走代理。
- **流**：增量每 30 毫秒合并一次，经 `ai-stream` 只发给发起请求的窗口；`ai_cancel` 只能取消本窗口的请求；窗口销毁时取消它的全部请求。
- **前端**：`prompts.ts` 构造消息，文档放在最前、问题放在最后；超过 `CONTEXT_BUDGET`（32,000 字符）的文档截断或分段摘要，并在抽屉里说明覆盖了多少。推荐问题由大纲在本地生成。回答经预览渲染器渲染，与文档一样被净化。对话只在当前窗口的内存里。PDF 取逐页提取的文字，没有文字层时不发请求。
- 测试用本机的模拟服务（Rust）或假的 `transport`（Vitest）。真实密钥不得出现在代码、日志、测试或文档里。

## 11. 设置与窗口

- **设置窗口**：标签 `settings`（`windows.rs` 的 `SETTINGS_WINDOW`），是独立的原生窗口，可以放到另一块屏幕。它不持有文档，运行 `useSettingsWindow.ts` 而不是工作区 hook，只能调用 4.1 中 `require_app_window` 一行的命令。页签为 `appearance`、`code`、`diagrams`、`typography`、`reading`、`workspace`、`ai`（`windows.rs` 的 `SETTINGS_TABS` 与前端的 `SettingsTab` 相同）。
- **打开**：菜单的 `preferences` 由 Rust 直接打开设置窗口，失败时才把 `menu-action` 发给文档窗口，退回到盖在文档上的对话框（`SettingsDialog`，浏览器预览也用它）。窗口先隐藏，页面载入设置后调用 `settings_window_ready` 才显示。设置窗口在前时 `⌘W` 关闭的是它。
- **实时生效**：设置窗口的修改 80 毫秒后写入；`update_settings` 之后 Rust 向所有窗口广播 `settings-changed`，文档窗口经 `settingsEffects.ts` 应用。`settingsSync.ts` 对对象类型的设置按内容比较，广播带回的新对象不会被当成又一次修改。窗口大小不随广播互相覆盖。
- **原生菜单**：在 `lib.rs` 的 `.menu()` 里搭建，文字与快捷键来自 `native_menu.rs`（`label`、`MENU_ITEMS`）。菜单事件发给聚焦的文档窗口（`focused_workspace`）。只有语言变化时才重设菜单文字与“最近打开”；`set_menu_state(kind)` 在窗口获得焦点和文档类型变化时调用，类型未变直接返回。Dock 菜单另有“新建窗口”。
- **右键菜单**：`contextMenu.ts` 的纯函数按点击位置与状态产出由菜单项 ID 组成的描述，`show_context_menu` 校验 ID（只能来自 `CONTEXT_ITEMS` 与主菜单）后弹出原生菜单。被选中的项以 `ctx:<窗口标签>:<id>` 回到 `lib.rs`，作为 `context-action` 发给弹出菜单的那个窗口，不会当成同名的主菜单项执行。剪切、拷贝、粘贴、全选用 AppKit 预置项。桌面应用里 WebKit 自带的右键菜单在输入框之外被屏蔽。
- **本地化有两处**：界面文案在 `src/app/i18n.ts`，原生菜单与右键菜单的文字在 `native_menu.rs`。新增菜单项或改语言相关的内容两处都要改。Rust 测试检查每个菜单项都有中英文且快捷键不冲突；`tests/context-menu.test.ts`、`tests/format-actions.test.ts` 检查前端用到的 ID 在 `native_menu.rs` 里有文字。
- **打开入口**：Finder 打开方式、Dock 拖入、拖进窗口统一进入 `IntentStore`，窗口收到 `open-intents-available` 后用 `take_open_intents` 领取。应用未就绪时先排队。拖入的图片交给编辑器，文件夹在文件栏打开。

## 12. 安全与离线边界

| 边界 | 内容 | 位置 |
| --- | --- | --- |
| 窗口权限 | `core:default`、调整窗口大小、退出、拖动窗口、设置窗口外观与背景色。没有文件系统、网络、shell 插件权限 | `src-tauri/capabilities/main.json` |
| CSP | `default-src 'self'; img-src 'self' data: blob: mino-asset:; style-src 'self' 'unsafe-inline'; font-src 'self' data:; script-src 'self'; connect-src ipc: http://ipc.localhost` | `tauri.conf.json` |
| 导航 | WebView 只能载入应用自己的入口页（开发构建另允许 `127.0.0.1:1420`）与空白框架 | `lib.rs` 的 `navigation_guard` |
| 外部链接 | 只有 `http`、`https`、`mailto` 交给系统打开；前端先经 `safeLinkHref` | `windows.rs` 的 `open_external`，`linkSafety.ts` |
| 网络 | 只有 `ai.rs`，且只在用户启用并同意之后 | 第 10 节 |

净化的位置：

- Markdown 预览、AI 回答、HTML / PDF / 打印的页面都经 `rehype-sanitize`；原始 HTML 不执行。公式用 KaTeX 的 `trust: false` 并限制最大尺寸（`KATEX_MAX_SIZE`）。
- Mermaid 的输出经 DOMPurify（`sanitizeDiagramSvg`）；图标标记来自随包的图标集，测试检查其中没有脚本、链接和 `url()`。
- 纯文本与源码预览逐字符转义，只输出固定的几种标签。
- 预览与导出不加载远程图片。
- 所有脚本、样式、字体、图标、语法包随包提供，运行时不访问 CDN。

不得添加的东西：

- 给 WebView 的文件系统、HTTP、shell 权限，或放宽 CSP（`connect-src`、`wasm-unsafe-eval`、远程源）。
- 前端的 `fetch`，包括为 PDF.js、字体或 AI 添加的。
- 接受前端传来的路径的文件命令。新的文件操作必须走令牌与授权。
- 跟随符号链接的读写；绕过 `atomic_write` 的文档保存；有损的编码写回。
- 把密钥、正文或完整路径写进日志、事件或错误码。

## 13. 性能规则

| 规则 | 检查 |
| --- | --- |
| 工作区 hook 不调用同步的 Markdown 解析器（`imageUrlsIn`、`rewriteImageUrls`、`hydrateMarkdown`），用 `analysisClient.ts` 的 `…Async` 版本 | `tests/main-thread-parsing.test.ts` |
| 分析、预览、导出渲染在 worker 里；worker 必须能启动 | `vite.config.ts` 的 `workerWithoutDom`，`tests/analysis-client.test.ts` |
| 入口包不含编辑器、CodeMirror、PDF.js、Mermaid、KaTeX，且不超预算；这些代码一律动态导入 | `vite.config.ts` 的 `entryBudget` |
| 应用外壳导入的模块不得依赖上述库：`findText.ts`、`syntaxRoleNames.ts`、`colorKey.ts`、`frontMatter.ts`、`fences.ts` 为此保持无依赖 | 同上 |
| 每秒变化多次的东西不进工作区 hook 的状态：AI 流式回答在 `AiStream`，面板拖动与捏合缩放直接写样式，滚动进度条在 `requestAnimationFrame` 里改 `transform` | `tests/render-scope.test.ts` |
| hook 的返回值经 `useStableFunctions`：处理函数身份不变并调用最新的闭包；渲染时调用且结果依赖状态的函数列入 `STABLE_EXCEPT`（目前只有 `t`） | `tests/render-scope.test.ts` |
| 文件栏、大纲、标签栏、状态栏是 `memo` 组件，只接收各自 `…Keys` 列表里的字段；组件开始读新字段时加进列表 | `tests/render-scope.test.ts` |
| 文档未变时不重算大纲、纯文本、字数；只移动光标时只算选区字数 | `tests/derived-data.test.ts` |
| 查找输入 120 毫秒防抖；装饰集只在匹配或当前项变化时重建；跳到第 N 项只定位一次 | `tests/find-performance.test.ts` |
| 关闭的标签立即释放编辑器实例 | `tests/app-shell.test.ts`，`tests/editor-pool.test.ts` |
| 切换风格、字体、配色、图表选项只改 CSS 变量或原地重画，不重建编辑器 | `tests/mermaid-restyle.test.ts`，`tests/reading-mode.test.ts` |
| 设置补丁只在语言变化时触及原生菜单；`set_menu_state` 在类型未变时不遍历菜单 | `settings.rs`、`native_menu.rs` 的测试 |
| 读写磁盘、哈希、解码的命令不在主线程；存储的锁不跨文件读写持有 | `#[tauri::command(async)]` 的约定 |
| 磁盘状态轮询先比较文件戳，未变不读文件 | `documents.rs` 的测试 |

`scripts/perf-baseline.mjs` 在 Node 里量解析、序列化、查找等耗时与包体积，只用于改动前后的对比，不代表 WebKit 里的绝对值。滚动、输入法、启动时间只能在打包后的应用里实机观察。

- **许可**：项目自身的许可未定，没有根 `LICENSE` / `NOTICE`；第三方许可清单已过期（见 §4.3）。
- **环境**：只在 Apple Silicon、macOS 27 上构建和使用过；声明的最低版本 macOS 12.0 没有实测。

## 2. 状态的含义

| 层级 | 含义 |
| --- | --- |
| codeComplete | 源码、配置、文档已实现，要求的运行检查还没有全部做完 |
| automatedVerified | 要求的自动化测试和构建有实际通过的结果 |
| nativeVerified | 在 macOS 上运行的应用里做过要求的操作，或检查过产物 |

- 状态只记在本文件，其他文档不复述。
- 离屏 WebKit 截图、无头 Chrome 截图、开发预览里的操作只算自动化证据，不算实机。
- 一处改动影响到已验证的行为时，相关验证要重做；失败的记录保留，不用后来的通过覆盖。
- 状态不是完成百分比；用户说“运行正常”是一条实机确认（记入 §5），不等于逐项验收。

## 4. 待办与未决事项

### 4.1 实机验收（步骤见 [验收清单](03-验收清单.md)）

1. 用 1.0.0 构建按清单逐部分验收。§3 表格最后一列就是各部分要查的内容；T81–T104 和 11-14 的代码审查改过打开、保存、草稿、查找、导出、PDF、菜单和启动的公共路径，此前零散的实机确认都要以当前构建为准重做。
2. 四个 Gate 全部 PENDING：GATE-1 技术路线（编辑、输入法、往返、图片、HTML、PDF 的实机闭环）、GATE-2 本地编辑（T07–T18 达到各自层级且没有未关闭的严重数据问题）、GATE-3 原生验收（验收清单的必需项通过）、GATE-4 本地交付准备（验收、性能、安装包、交接齐全）。
3. 需要用户自己的条件才能做的：真实 AI 密钥（密钥不得进入记录、日志、截图）、打印机、macOS 12–13 的机器、第二块显示器。
4. 实机操作由用户手动执行，代理只提供步骤清单，不驱动鼠标键盘。

### 4.2 等用户决定

1. 项目自身的许可，以及随包的 notices。
2. 是否签名、公证，是否提供可下载的安装包。
3. 是否删除非 macOS 的平行实现（约 150 行，在 macOS 上不编译，部分是测试的对照读取器），见 [代码复用约定](05-代码复用约定.md)。
4. 源码编辑器是否跟随阅读风格与代码配色变色（T110 写明不在范围内）。
5. 默认字号统一为 15：用户已确认照现状保留（11-12），此处只留记录。

### 4.3 已知缺陷与未做的事

1. T109：打开文档后文件栏拖动失效，原因未查明（之后加了保存与移动之间的锁，没有记录是否因此解决）。
2. webview 无响应时 Dock 的“退出”被挡住（强制超时可能丢失未保存内容，未做）。
3. `useDocumentWorkspace.ts` 的拆分（纯重构，未安排）；这个 hook 没有组件级测试。
4. 第三方许可清单过期：两份 npm 清单在 T90 之前就缺 mermaid、jsdom、rehype 等约 160 个包，之后又没有补 `@iconify-json/lucide`、`roughjs` 和 T117 新增的字体包（其中几款已被 T118 取消）；2026-11-07 的审查里 npm 295 个包中 5 个、Rust 258 个包中 15 个在本机找不到许可原文。许可文本合集不随包。发布前需重新生成并核对（`scripts/generate-license-text-bundle.py`）。随包字体的来源与许可在 `licenses/bundled-font-licenses.tsv`，这份是当前的；2026-11-07 的审查记录是 `licenses/license-text-audit.md`。

7. F05 表格竖线转义修复后的浏览器往返一直没有重跑。

### 4.4 性能：已有的数字与没量过的

- 体积：`Mino.app` 63.60 MiB（T104，预算 80 MiB；之后字体有增减，未重新量）；随包字体 51.8 MiB（预算 56 MiB）；入口包预算 685,000 字节，由构建检查守护。
- 已量过（离屏或测试进程内，不是实机）：入口包 3,122,055 → 约 62 万字节；10,000 个文件的全文搜索单次 889 ms；SHA-256（64 MiB）118 → 25 ms；1.95 MiB 富内容文档以阅读模式打开，开头约 1.0 s、整篇约 4.5 s（原约 27 s）；每步滚动约 260 → 20 ms（原因是渲染层数量，不是字体）。
- 未解决：1.95 MiB 富内容文档进入编辑仍约 26 s。
- 从未运行：`scripts/performance-session.mjs` 的正式会话（需要 release 包；10,023 个固定样本已生成）；启动、空闲内存、输入延迟、目录首屏、大 PDF 打开耗时的实机测量。

## 7. 记录方式

- **范围变化**（新功能、用户否定后重做、取消某项）：在 §6 加一行，写日期、做了什么、取代了什么；需要任务号时从 T121 接着编。同时按顺序更新 [产品说明](01-产品说明.md)、[技术设计](02-技术设计.md)、[验收清单](03-验收清单.md)。
- **状态变化**：改 §3 对应部分的三列。某一项实机查过了，就把它从“尚未验证”移到“实机验证”，写上日期和构建；全部任务都查过才能写该部分已实机验证。失败照样记。
- **待办**：解决的从 §4 删掉，新发现的加进去；用户做了决定的，把结论写进 §6 再从 §4.2 删掉。
- **用户的实机反馈**：在 §5 加一行，原话的意思照实写，不拔高为验收。
- **数字**：只保留当前有效的体积、预算和测量；测试通过数只在 §1 留最近一次。
- **证据文件**：不再为每个任务建。只有检查产出了值得留的东西（样张、测量数据、许可清单、探针结论）才留下文件（许可相关的在 `licenses/`），并在这里指到它。
- 头部的版本与更新日期随每次修改更新；对使用者可见的变化另记入 [发布日志](../CHANGELOG.md)。

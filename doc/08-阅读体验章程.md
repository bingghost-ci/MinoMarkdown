# Mino 阅读体验章程

版本：v0.5 · 日期：2026-11-11 · 状态：v0.5 记录用户试用 T61–T73 后的调整（T74–T77）：夜间风格改为五种、风格共 12 种，编辑器代码块外观，见 §18；v0.3 对应的 T51–T60 已完成代码（实现差异见 §16）；v0.4 记录 2026-11-11 的范围变化，新增 T61–T73，重做风格目录、界面色、纸张材质与字体方案，与 v0.3 的差异见 §17，v0.4 的内容均为计划。任务状态只在[开发进度](06-开发进度.md)维护，技术风险见根目录 [README](../README.md#已知技术风险)。

## 1. 背景与定位

2026-11-11 用户反馈：T50 实现的纸张纹理看起来脏；希望提供多种纸张风格（如牛皮纸、羊皮卷、宣纸）和护眼风格；明确 Mino 主打方便阅读，先把极致的阅读体验做好，字体、Markdown 文本展示、HTML/PDF 导出和图片都要带上统一的风格。

Mino 的定位因此调整为**以阅读为先的 Markdown 工具**：打开文档首先是读，编辑是辅助能力。本章程定义这一轮的目标、原则、风格体系、实现方案和开发计划，取代 T42–T48 中“HTML/PDF 导出字体固定、不随编辑器变化”的约束。

2026-11-11 用户审阅 T51–T60 的结果后再次反馈（v0.4）：对现有全部 14 种风格不满意（“都很丑”），以微信读书网页版为参照：中性灰画布上一张干净的大圆角纸面，颜色只用在标题上，右侧一列悬浮圆形按钮，弹出式字体面板（字号滑杆加用各自字体渲染的字体网格），浅色与深色两套。纸张、羊皮卷风格“要有纹路，要有质地感”；字体要更多，并同时照顾中文和英文文档；希望集成 ChatGPT 或 DeepSeek 的 API 做类似“AI 问书”的分析功能。

对 T51–T60 结果的诊断（v0.4 要解决的问题）：

| 问题 | T51–T60 的结果 | 影响 |
| --- | --- | --- |
| 风格分不开 | 书页、羊皮卷、暖黄、低蓝光、宣纸五种米黄色风格色差很小 | 14 种里实际可辨的不多 |
| 界面跟着染色 | 侧栏、工具栏、画布由纸面色派生 | 整屏一片黄或绿，纸面不突出 |
| 纹理认不出纸种 | 256px 程序噪点，没有纤维、帘纹和纸边 | 只是“有点颗粒”，没有质地感 |
| 纸面单薄 | 直角、弱阴影 | 不像一张纸 |
| 字体太少 | 只有 4 个预设，西文只有 Georgia / SF 兜底 | 英文文档观感差，中文可选项少 |

v0.3 立项时（T51 之前）审查发现的问题：

| 问题 | 现状 | 影响 |
| --- | --- | --- |
| 纹理发脏 | T50 用运行时 SVG 噪点，其中低频“纤维斑”是比纸面更深的大块暗影 | 看起来像污渍，不像纸 |
| 风格无单一来源 | 主题色写在 `styles.css`，导出样式写死在 `renderHtml.ts`，预览又是另一套选择器 | 屏幕、预览、HTML、PDF 观感不一致 |
| 导出无风格 | HTML/PDF 固定白底、系统无衬线、760px 宽 | 导出物与阅读时看到的不一样 |
| 排版参数少 | 只有字体、字号、行高 | 段距、行宽、对齐、缩进、中文标点都无法调 |
| 字体受限 | 只能用系统字体，系统缺少适合屏幕长读的中文书宋与文楷 | 中文长文观感一般 |
| 编辑控件干扰阅读 | 块把手、浮动工具栏、编辑工具栏常驻 | 读长文时分心 |
| 图片无处理 | 图片原样放置，无图注，夜间刺眼 | 图文混排不协调 |

## 2. 目标

一句话：**在 Mino 里读一篇 Markdown，应当像读一本排得好的书，导出后也一样。**

| 目标 | 衡量方式 |
| --- | --- |
| 一致 | 编辑器、源码保护预览、HTML、PDF 使用同一份风格数据生成样式；同一文档四处并排截图，颜色、字体、间距一致 |
| 舒适 | 正文对比度在 7:1–15:1 之间（护眼风格避免纯黑配纯白），次要文字、链接和用强调色的标题不低于 4.5:1；行高 1.6–2.0；可选行宽 30–42 个汉字，西文文档按字符数换算 |
| 有质感且干净 | 每种纸张能被认出纸种；纹理不形成可见污渍；“可辨认”和“干净”都由纹理质量测试量化（§4.4） |
| 纸面突出 | 画布与界面是中性色，颜色只出现在纸面和标题上；任何风格下界面都不被染色（2026-11-14 起由 T108 调整为灰色向纸色靠拢 30%，界面文字仍为中性，见 §4.3） |
| 不打扰 | 打开文件即进入阅读模式，无编辑控件；切换风格不重建编辑器、不丢光标和撤销栈；2 MiB 文档滚动不因纹理或字体掉帧 |

## 3. 原则（不可违反）

- **只改呈现，不改文档。** 不向 Markdown 写入任何风格信息，图注等只在渲染时生成。
- **默认离线。** 纹理和字体随包，不从网络加载；导出物不引用外部资源；HTML 净化规则不放宽。导出 HTML 的 CSP 只为内嵌字体把 `font-src` 从 `'none'` 改为 `data:`，其余不变。v0.4 起产品定位为“默认离线，AI 为用户主动开启的可选联网功能”：webview 仍然没有任何网络权限，CSP 不变，只有 Rust 进程在用户开启 AI 并同意后向用户配置的地址发请求；不开启 AI 时应用行为与以前完全一样。阅读风格、纹理和字体与 AI 无关，始终离线可用。
- **单一来源。** 风格是数据，CSS 由数据生成，所有出口共用。
- **可测。** 对比度、风格完整性、纹理质量、字体体积、导出无外链都有自动化测试。
- **兼容。** 旧设置文件缺新字段时取默认值。v0.4 起已移除的风格 ID 和旧字体字段在读取设置时按映射表迁移（§4.2、§5.2），不得因旧值回退到默认设置。
- **有预算。** v0.4：纹理每种纸 ≤ 700 KiB、合计 ≤ 2 MiB；应用体积 ≤ 80 MiB，随包字体的分项上限由 T69 按实测确定；导出 HTML 内嵌字体 ≤ 6 MiB，超出时改用系统字体回退并提示；导出 HTML 内嵌纹理的预算（v0.3 为 ≤ 400 KiB）由 T63 实测后确定为每种纸源文件 ≤ 450 KiB（实测 192–427 KiB）；随包字体上限由 T69 定为 48 MiB（实测 42.42 MiB）。v0.3 的预算为纹理总量 ≤ 1 MiB、单张 ≤ 150 KiB，随包字体 ≤ 32 MiB。

## 4. 风格体系

### 4.1 概念

**阅读风格** = 纸面（底色、纹理、圆角、阴影）+ 墨色（正文、次要文字、链接、代码、引用、表格线）+ 强调色（一、二级标题和界面强调）+ 明暗归属（浅色或深色，决定使用哪一套界面色）+ 推荐字体 + 图片处理 + 打印变体。画布和界面色不属于风格（§4.3）。

字体与排版是独立设置，风格只提供推荐默认值，用户改过字体后不再随风格切换。“跟随系统”时，白天和夜间各选一个风格，默认白天“白”、夜间“深灰”（以代码 `defaultReadingSettings` 为准；v0.4 文本曾写白天“书页”；v0.3 的默认夜间风格“夜读”已并入“深色”；v0.5 起 `dark` 改名“深灰”）。

### 4.2 风格目录与初始色值

v0.4 把风格精简为 9 种并重做（T62），不在 v0.3 的 14 种上微调；v0.3 的目录保留在 §17.1。纸面与正文是初始色值，对比度为 WCAG 计算值；次要文字与强调色的准确色值在实现时于对比度测试约束下确定（正文 ≥ 7:1，次要文字、链接与标题 ≥ 4.5:1），本表只给出色相。样张出来后可微调，但必须继续满足 §2。

### 4.3 画布与界面色

v0.4 取代 v0.3“界面色由纸面色向中性灰靠拢派生”的规则（T61），原因是派生色让整屏跟着纸面发黄或发绿：

- **画布**（纸面之外的区域）是不随纸面染色的中性灰：浅色风格约 `#f2f3f5`，深色风格约 `#1c1c1e`。
- **界面色**（侧栏、工具栏、标签栏、状态栏）只有浅、深两套中性色，由风格的明暗归属选择，不含纸面的色相。界面中随风格变化的只有强调色（选中态、焦点、按钮高亮）。
- **纸面**是画布上的大圆角卡片：圆角 14px、柔和阴影、更大的页边距，不画纸边线。
- **标题与正文**：一、二级标题使用风格的强调色，三级及以下用正文色；正文用柔和深灰（浅色风格）或浅灰（深色风格），不用纯黑或纯白。
- **2026-11-14 调整（T108）：** 用户在“保持中性灰”“淡淡染色”“明显染色”中选了“淡淡染色”。画布与界面色由上面两套中性灰各自向纸面色混合 30%（`styles.ts` 的 `CHROME_TINT`）：暖纸配暖灰，豆沙绿配带绿的灰；界面文字与次要文字仍为中性，强调色规则不变。系统标题栏去掉，红绿灯放在应用顶行；窗口的浅色或深色外观跟随风格。上两条中“不随纸面染色”“不含纸面的色相”自此不再适用。
- **界面外观**（T64）：工具栏、标签栏、侧栏去掉重边框并弱化；编辑区右侧一列悬浮圆形按钮承担目录、字体与风格面板、AI（仅启用后出现）、日夜切换、阅读/编辑切换。

### 4.4 纸张材质

v0.4 重做材质（T63）。v0.3 的 256px 图块只有颗粒和短线，认不出纸种；新材质按纸种分别制作，并保持 v0.3 “不做大块脏斑”的底线。

- **生成方式不变：** `scripts/generate-paper-textures.mjs` 用固定随机种子离线生成，结果可复现，PNG 编码只用 Node 自带的 zlib，不新增依赖；产物提交到 `src/assets/paper/`。不用运行时 SVG 噪点。
- **分层透明图块：** 每种纸一组图块，分为细颗粒层与大周期结构层（结构层可按纤维、帘纹、色斑、毛孔等再分张），无缝周期 ≥ 1024px，避免平铺时看出重复。

| 风格 | 结构 | 说明 |
| --- | --- | --- |
| 书页 | 细压纹 | 均匀、克制，接近书籍内页 |
| 宣纸 | 长纤维 + 帘纹 | 纤维长而浅，帘纹为等距的细横纹 |
| 羊皮卷 | 云状色斑 + 毛孔 | 四周做旧暗角由 CSS 实现，不画进图块；正文区保持可读 |
| 牛皮纸 | 横向纤维 + 杂点 | 纤维有明确方向，杂点稀疏 |

- **纹理强度：** 新增设置 `textureStrength`（0–100，默认 60），通过在纹理上叠一层纸面色实现：0 为纯色纸面，100 为纹理全显。不使用滤镜或混合模式，不影响正文对比度与滚动性能。
- **预算：** 每种纸 ≤ 700 KiB，合计 ≤ 2 MiB。
- **质量测试：** “干净”——图块平铺无接缝（对边像素差上限）；强度 100 下按纹理最暗 5% 分位计算的正文对比度仍满足 §2。“可辨认”——每个纸种对其结构设下限，例如纤维方向性、帘纹周期、色斑尺度。v0.3 的“32 px 以上低频亮度起伏上限”改为按纸种设上下限，因为羊皮卷的色斑本身是低频结构；各阈值在 T63 定稿并写入证据。
- **样张：** 每种材质在编辑器中截取 1:1 局部图，放入 `doc/evidence/`，由用户逐个确认。

## 5. 字体与排版

### 5.1 字体来源

v0.4 的字体方案是“随包少量开源字体 + 读取系统已装字体”（T66–T68），取代 v0.3 只有两款随包字体加系统字体预设的做法。v0.3 的随包字体表保留在 §17.3。

| 来源 | 字体 | 说明 |
| --- | --- | --- |
| 随包中文（现有） | 思源宋体（`@fontsource/noto-serif-sc` 5.3.1，400/700，按区段分片）、霞鹜文楷（`@fontsource/lxgw-wenkai` 5.3.0，500/700，整体文件） | T55 已随包，OFL-1.1 |
| 随包中文（T66 候选） | 思源黑体、霞鹜新晰黑、朱雀仿宋、寒蝉活宋、汇文明朝体、京华老宋体 | 逐款核对授权，只收录明确允许随应用再分发、转换为 WOFF2 并嵌入导出 HTML 的字体；名单以 T66 证据为准 |
| 随包西文（T68） | Source Serif 4、Literata、EB Garamond、Inter、JetBrains Mono | 均 OFL，仅 latin / latin-ext 子集 |
| 本机字体（T67） | 系统已安装的任意字体族 | 只读取族名列表；设置中以 `sys:<族名>` 保存；族名在生成 CSS 前转义 |

- 商业字体（方正、仓耳、汉仪等）一律不随包，用户自行安装后可在“本机字体”中选用。
- 随包字体只保留 woff2；`@font-face` 使用 `font-display: block`；每款的许可原文加入第三方许可清单和 `generate-license-text-bundle.py`。应用 CSP 已允许 `font-src 'self'`，无需修改。
- 代码块与行内代码使用随包等宽字体 JetBrains Mono。
- 本机字体不内嵌进导出 HTML，导出时按族名引用并提示在其他机器上观感可能变化；随包字体的内嵌规则见 §9。
- 体积：v0.3 实测随包字体 20.4 MiB，应用 36.82 MiB。v0.4 的应用体积预算为 ≤ 80 MiB，每类字体的实际增量由 T69 记录。

### 5.2 中文字体与西文字体

v0.4 取消“字体预设”，改为中文字体和西文字体分开选择（T68）：设置字段 `cjkFont` 与 `latinFont` 取代 `fontPreset` / `editorFont`，旧值在读取时迁移。v0.3 的预设表保留在 §17.3。

- 字体栈中西文字体排在中文字体前，保证中西文各用其字体；随包与本机字体之后接系统字体作为回退。
- 两个字段都可以选“跟随风格”，使用 §4.2 的推荐字体；用户选过具体字体后不再随风格切换。
- 字体在弹出面板的字体网格中选择（T65）：每个按钮用自身字体渲染，分“中文 / 西文 / 本机”三组，本机字体可搜索。

### 5.3 排版参数

- **段间距**：紧凑 / 标准 / 宽松（0.5 / 0.9 / 1.3 em）。
- **行宽**：30 / 36 / 42 个汉字 / 不限。“不限”沿用 T42 的 1040px；新安装默认 36 字，已有用户保持原宽度。
- **对齐**：左对齐 / 两端对齐，两端对齐用 `text-justify: inter-character`。
- **首行缩进**：无 / 2 字，只作用于正文段落，不作用于列表、引用、表格。
- **中文标点与中西文间距**：WebKit 支持 `text-spacing-trim`、`text-autospace` 时启用，用 `CSS.supports` 检测，只影响显示。
- **标题**：字号模数 1.25，标题与正文同族字体加粗；羊皮卷、宣纸的一级标题居中，分隔线改为花饰。v0.4：一、二级标题用风格的强调色。

### 5.4 西文排版（v0.4，T68）

以西文为主的文档自动使用西文排版：两端对齐、`hyphens: auto` 并设置 `lang`、较小的行高、按字符数换算的行宽。是否以西文为主，按正文中 CJK 字符与拉丁字母的占比判定，代码、链接地址和公式不计入。由设置 `latinLayout`（`auto` / `off`，默认 `auto`）控制；`lang` 只加在渲染结果上，不写入 Markdown。判定阈值在 T68 定稿。

## 6. Markdown 元素呈现

编辑器（Crepe 的 `.ProseMirror`）与预览、导出（HTML 字符串）的 DOM 不同：共用同一组 CSS 变量，分别写两套选择器。预览与导出统一使用 `.mino-doc` 容器类，避免第三套样式。

| 元素 | 设计 |
| --- | --- |
| 段落、标题 | 按 §5 参数；v0.4：一、二级标题用强调色，三级及以下用正文色（v0.3 为“标题墨色略深于正文”） |
| 列表、任务列表 | 列表标记用次要色；任务列表使用与风格相符的方形勾选框 |
| 引用 | 左侧 3px 细线，文字用次要色；书页、羊皮卷、宣纸改用左上角大引号装饰 |
| 代码块 | 纸面色加深 4% 的底色，无边框，圆角 4px；语法高亮按浅色、暖色、夜间三套配色。v0.5（T75）：编辑器中的代码块行号栏透明、行号用弱化墨色，语言选择与复制按钮为纸面色的扁平样式，圆角 8px；选项与属性名、属性键名（JSON 的键）和内置命令也上色，编辑器与预览、导出共用同一份高亮定义 |
| 行内代码 | 等宽字体（v0.4 为随包 JetBrains Mono），浅底，颜色随风格的链接/强调色 |

| 链接 | 链接色加 1px 下划线，偏移 3px（v0.3 的“水墨屏只用下划线”随该风格并入灰白而取消） |

## 7. 图片

- 居中，最大宽度不超过行宽，圆角 3px。纸张风格像贴在纸上的照片：6px 浅色衬边加轻投影；护眼和夜间风格只用 1px 细边框。v0.4 不再有“纸张 / 护眼 / 夜间”分组：有纹理的书页、宣纸、羊皮卷、牛皮纸用衬边，其余五种用细边框；“夜间风格”指深色与纯黑。v0.5：无纹理的风格为八种，“夜间风格”指淡黑、深灰、中灰、青灰、暖灰。
- 有 title 或 alt 时在图下以次要色、小一号字显示图注，只渲染不改文档，可在设置中关闭。
- 夜间风格默认把图片亮度降到 90%，可关闭；小于行宽的图片不放大。
- 阅读模式下点击图片放大查看，背景压暗，Esc 或再次点击关闭。
- 导出时保持同样的衬边与图注；打印时图片不跨页，最大高度为页面可用高度。

## 8. 阅读模式（已确认默认进入）

- **何时进入：** 从文件、Finder、拖入、最近使用打开的文档默认进入阅读模式；新建的“未命名”文档、从草稿恢复的文档、有未保存修改的文档直接进入编辑模式。设置中可改为“打开时直接编辑”。
- **切换：** “视图 > 阅读模式”，快捷键 `⌘⇧R`（现有快捷键未占用，`⌘E` 已用于行内代码）。阅读模式右上角有一个“编辑”按钮，编辑模式工具栏右侧有“阅读”按钮。在阅读模式中按字母键不会修改文档，状态栏提示“按 ⌘⇧R 开始编辑”。
- **界面：** 隐藏编辑工具栏、块把手、浮动格式工具栏和斜杠菜单；顶部显示一条很细的阅读进度条；侧栏按原设置显示；大纲、查找、缩放、复制可用。
- **翻页：** 空格 / Shift+空格按一屏减两行翻页，方向键平滑滚动，`Home` / `End` 到首尾。
- **位置：** 会话内记住每个文档的滚动位置，切换标签再回来时恢复。
- **v0.4（T64）：** 阅读模式只留纸面，工具栏和状态栏都隐藏，靠编辑区右侧的悬浮按钮和快捷键操作；“编辑 / 阅读”切换改由悬浮按钮承担，状态栏的“按 ⌘⇧R 开始编辑”提示改为按钮提示。何时进入、只读行为、翻页、阅读位置和 `⌘⇧R` 不变。
- **实现：** 通过 Crepe 的只读状态切换，不重建编辑器，不影响撤销栈、未保存状态和草稿；源码保护文档本来就显示预览，阅读模式只隐藏“编辑源码”之外的编辑入口。

## 9. 导出 HTML 与 PDF

- 导出时可选“导出风格”：当前阅读风格（默认）或简洁白底。
- **HTML：** 样式由同一份风格数据生成后内联；纹理以 data URI 内嵌。字体只内嵌文档实际用到字符所在的 woff2 分片，按字符计算所需分片，不引入子集化依赖；超过 6 MiB 时改用系统字体回退栈并在结果中提示。导出 CSP 只把 `font-src` 改为 `data:`，净化规则不变。
- **PDF / 打印：** 导出 PDF 与打印分开（T106）。导出 PDF 套用导出风格，纸色铺满整页（含页边距，在打印后用 PDFKit 铺底），每页页边距一致，纸张纹理不导出。以下两种模式只作用于打印：“打印友好”用白底，保留字体、排版、表格和图片样式，夜间风格改用深色墨水，是所有风格的默认。“与屏幕一致”在打印区域内铺纸张底色和纹理，页边距为白色（T52：WebKit 无法同时做到满版纸色和每页一致的页边距）。页面设置提供 A4 / Letter 和窄 / 标准 / 宽三档页边距（12 / 18 / 25 mm）。PDF 中的字体由 WebKit 按用到的字符子集嵌入。霞鹜文楷没有分片，HTML 导出总会超出 6 MiB 而回退系统楷体，打印不受影响。
- 打印背景、满版边距、页码等技术限制见根目录 README 的“已知技术风险”，由 T52 先行验证。

## 11. 技术架构

- `src/features/reading/styles.ts`：风格数据与类型，界面色由纸面按 §4.3 推导。
- `src/features/reading/css.ts`：风格数据生成 CSS 变量和 `.mino-doc` 元素样式；应用、预览和导出都调用它。`styles.css` 只保留编辑器专属的选择器映射。
- `src/features/reading/fonts.ts`：随包字体的 `@font-face` 导入、字体预设到 `font-family` 的映射，以及导出时按字符挑选分片。
- 纹理通过 Vite 导入，应用内按 `'self'` 加载；导出时由主线程读取纹理和字体分片的字节转为 data URI，再连同 CSS 字符串传给导出 worker。T63 的实现曾把全部纹理以 data URI 内联进入口包（约 1.4 MB），T98 改回这里描述的做法。随包字体的 `@font-face` 规则自 T98 起是生成的样式表 `bundledFonts.css`，字体表 `fontTable.ts` 只在导出时加载，两者由 `scripts/generate-font-table.mjs` 生成。`renderExport` 增加样式参数，替换写死的 `stylesheet`。
- Mermaid 主题变量、KaTeX 颜色从当前风格读取；切换风格时只在页面中已有 Mermaid 图时按新主题原地重绘（`restyleDiagrams`），不重建编辑器。
- 代码高亮：编辑器沿用 CodeMirror；预览与导出在净化之后由 `rehypeHighlightCode` 用已安装的 `@codemirror/language-data` 与 `@lezer/highlight` 解析，只输出固定的 `tok-<角色>` 类名，颜色取自风格的语法变量（单块 10 万、单文档 50 万字符以上不高亮）。
- 数字列右对齐：预览与导出在净化后给未写对齐的数字列加 `mino-num` 类，编辑器用 ProseMirror 装饰实现，不改文档。
- 阅读模式状态放在每个标签的会话状态中，`EditorAdapter` 增加只读切换，不重建 Crepe。
- 打印：背景由导出样式中的 CSS `print-color-adjust: exact` 开启，不需要 Rust 命令（T52）。导出时主线程通过 `read_app_asset` 读取应用包内的 `/assets/*.woff2` 字体分片，以及所用风格的纸张纹理层（`/assets/` 下以 `paper-`、`xuan-`、`parchment-`、`kraft-` 开头的 PNG，T98 起），该命令不接触用户文件。`tauri dev` 下随包字体与纹理由 Vite 内联导入读取（`appAssets.ts`），开发态导出也内嵌字体与纹理。
- 自动化测试：风格完整性、对比度、CSS 生成快照、纹理质量、字体体积预算、导出 HTML 无外部引用、导出字体分片选择、设置校验与旧值兼容、阅读模式不改文档。
- 视觉样张：本轮使用的离屏 WKWebView 截图工具收入 `scripts/`，按风格批量生成样张到 `doc/evidence/`，作为人工审阅材料，不自动判定通过。

- **v0.4 计划的改动**（详见[技术设计 §19](02-技术设计.md)，实现前核对代码）：`styles.ts` 增加浅、深两套中性界面色和风格的明暗归属、强调色，删除由纸面推导界面色的函数；`css.ts` 生成圆角纸面、强调色标题和纹理强度变量；`fonts.ts` 改为字体注册表，支持 `sys:<族名>` 并统一转义；新增只读命令 `list_system_fonts`；西文排版判定为纯函数；悬浮按钮与弹出面板为 `src/app/components/` 下的新组件。

### 17.2 v0.3 的界面色与纸张材质（已由 §4.3、§4.4 取代）

**界面色：**

工具栏、标签栏、侧栏不直接使用纸面色，而是纸面色向中性灰靠拢后的浅色版本（夜间风格为深色版本），饱和度不超过纸面的一半。这样界面安静，视觉重心落在纸上，也避免上一版“整片泥灰”的问题。

**纸张材质：**

- **不再用运行时 SVG 噪点。** 改为离线生成的无缝 PNG 图块：`scripts/generate-paper-textures.mjs` 用固定随机种子生成，PNG 编码只用 Node 自带的 zlib，不新增依赖；产物提交到 `src/assets/paper/`。
- **分层：** 底色（CSS）+ 纤维层 + 颗粒层。纤维用与纸面同色相、略亮或略暗的细长线条，不做大块暗斑；宣纸的纤维更长、更浅，牛皮纸的纤维短而密；羊皮卷的做旧只用 CSS 径向渐变压在纸张四周，正文区保持干净。
- **质量测试：** 图块平铺无接缝（对边像素差上限）；亮度标准差上限；32 px 以上尺度的低频亮度起伏上限，这一项专门防止“脏”；按纹理最暗 5% 分位计算的正文对比度仍满足 §2。
- **样张：** 每种材质在编辑器中截取 1:1 局部图，放入 `doc/evidence/`，由用户逐个确认。

### 17.3 v0.3 的随包字体与字体预设（已由 §5.1、§5.2 取代）

| 字体 | npm 包 | 授权 | 字重 | 估计增量 |
| --- | --- | --- | --- | --- |
| 思源宋体（Noto Serif SC，与 Source Han Serif 同设计） | `@fontsource/noto-serif-sc` 5.3.1 | OFL-1.1 | 400、700 | 约 11 MiB |
| 霞鹜文楷 | `@fontsource/lxgw-wenkai` 5.3.0 | OFL-1.1 | 500、700（该版本无 400） | 约 14 MiB |

- 思源宋体按 Unicode 区段切成大量小 woff2 分片，并用 `unicode-range` 声明，WebKit 只加载文档实际用到的分片。霞鹜文楷 5.3.0 每个字重是单个 7–9 MiB 的 woff2，没有分片，首次使用时整体加载。

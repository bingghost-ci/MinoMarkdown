# Mino 分步开发计划

版本：v0.1 · 日期：2026-11-06 · 上游：[技术设计](02-技术设计.md)。

## 执行规则

本计划分为 5 个里程碑、29 个任务。建议按 T01→T29 顺序执行；每个任务的输入、实施、产物、完成条件和失败处理如下。最终验收依赖必须达到指定完成层级；开发阶段核对实际代码与接口即可衔接下一项，不能仅检查文件是否存在。任务状态只写入 [开发进度](06-开发进度.md)。

本计划制定时所有任务均未开始。后续执行状态以[开发进度](06-开发进度.md)为准；下文路径和命令描述计划产物，实际存在性需逐项检查。

2026-11-07 用户调整执行节奏：先完成全部功能开发，最后由用户集中实测，再据结果优化。开发阶段按 T01→T29 的代码依赖顺序推进，可运行代理可独立完成的类型、单元、构建检查；同一检查最多执行 3 次，仍失败则记录并继续不依赖该结果的开发，不逐项要求用户操作原生应用。原计划的 `nativeVerified` 完成层级与 GATE-1/2/3/4 验收标准保留，未测一律 `PENDING`，开发阶段最多记 `codeComplete` 或有相应证据的 `automatedVerified`。下文涉及“Gate PASS 后继续”的语句仅适用于最终验收顺序；开发阶段不以原生 Gate 为下一项代码工作的前置条件。集中实测后再逐项补证据和修复。

## T01 建立工程与锁定依赖

**依赖：** 无。**设计入口：** 技术设计 §1–3、§11、§13。**覆盖：** E05、E06。**完成层级：** automatedVerified。

**输入：** 本套文档、可用 macOS 工具链；保留原始需求和现有 doc 文件。

**实施步骤：**

1. 记录系统、架构、Node/包管理器/Rust；建立 Tauri 2 + React + TypeScript + Vite 最小工程，配置单主窗口。
2. 检查并固定 Tauri、Milkdown/Crepe、解析/净化/测试依赖与工具链；生成依赖锁文件、许可证清单和最小权限配置，不启用不需要的插件。
3. 提供开发、类型检查、测试和构建脚本；所有编辑器资源使用本地依赖，文档说明实际命令。

**产物：** package.json、依赖锁文件、src/、src-tauri/、工具链配置；doc/evidence/dependency-baseline.md。

**完成条件：**

- 依赖安装、类型检查、Rust 编译检查和最小应用构建有真实结果；没有运行时 CDN，所锁发行包的编辑入口可定位。
- 文档中写明实际版本/许可证、命令和系统环境；没有覆盖原始需求或自动初始化远程仓库。

**失败处理：** 工具链/网络不可用时记录精确错误与缺少项，不编造锁文件和成功日志；先完成可独立的工程配置。

**完成后：** T02，建立可验证的语法基线。

## T02 建立语法样本与兼容性基线

**依赖：** T01。**设计入口：** 技术设计 §6、§12–13。**覆盖：** A03、A13、E02。**完成层级：** automatedVerified。

**输入：** 锁定的 Markdown 解析链；验收文档 F01–F12 样本设计。

**实施步骤：**

1. 建立包含原始字节期望值的 Markdown/图片 fixtures，覆盖普通语法、front matter、CRLF/BOM、引用式链接、表格转义和未知结构。
2. 实现最小 parse/serialize/兼容性报告工具，比较语义字段与未覆盖源码，不以 HTML 一致代替往返检查。
3. 提供可重复的检查入口和样本清单，合成图片并记录用途，不使用私人文档。

**产物：** tests/fixtures/、src/core/markdown/ 基础模块；doc/evidence/T02-markdown-baseline.md。

**完成条件：**

- 已支持样本往返语义保持；未知 HTML/扩展产生源码保护报告；故意丢失或改写 front matter 的反例能被检查检出。
- 有故意损坏链接目标/代码内容的反例，证明检查能发现数据损失。

**失败处理：** 解析器无法稳定处理常见语法时保留失败样本，列为 T03/T06 选型输入，不能删掉样本让检查变绿。

**完成后：** T03，验证真正的编辑交互。

## T03 验证编辑器、中文输入和工具栏

**依赖：** T01、T02。**设计入口：** 技术设计 §1、§4、§6。**覆盖：** R04、R05、R08、A03–A05。**完成层级：** nativeVerified。

**输入：** 锁定 Crepe 发行包、T02 样本、macOS 系统中文输入法。

**实施步骤：**

1. 实现薄 EditorAdapter，载入 Markdown；启用所需语法，关闭 AI/公式等首版外功能。
2. 验证并接入 TopBar，或实现应用工具栏原型；测试选区、链接弹层、undo/redo 与输入规则。
3. 在实际 Tauri WebView 完成连续中文和中英文混输、组合输入后加粗、列表/代码中的输入，并记录版本与操作。

**产物：** src/features/editor/ 原型与适配器；doc/evidence/T03-editor-spike.md、实机截图/操作记录。

**完成条件：**

- 原生应用默认可视化；中文无吞字、重复或光标跳动；加粗作用于原选区且可撤销。
- 原需求的快捷输入在正确上下文生效，转义与代码区不误转换；T02 样本经编辑器往返仍通过。

**失败处理：** 先定位事务/组合输入原因再改动；常见编辑不能可靠完成时，不推进目录 UI；必要时定向比较备选并交 T06 决策。

**完成后：** T04，串通本地单文件和图片。

## T04 验证单文件与截图持久化闭环

**依赖：** T03。**设计入口：** 技术设计 §5、§7–8、§11。**覆盖：** R03、R06、A02、A06、A07。**完成层级：** nativeVerified。

**输入：** 可运行编辑器原型、仅含合成样本的临时目录、实际 macOS 截图。

**实施步骤：**

1. 通过原生对话框打开测试 MD，以最小受限 Rust 文件服务读写；保存使用临时文件和替换，不在前端任意访问磁盘。
2. 接通剪贴板图像到 assets 的最小链路；未命名文档先入草稿，首次保存迁移并改相对引用。
3. 关闭并重开验证图片；检查中文/空格路径、重名、取消保存和资源失败；记录二进制 IPC 与截图格式策略。

**产物：** 文件/图片 POC 与草稿最小实现；doc/evidence/T04-file-image-spike.md。

**完成条件：**

- 单文件打开→编辑→粘真实截图→保存→关闭重开后文字和图片完整，最终 MD 无 blob/临时路径。
- 新文档先粘图再保存成功；取消不丢草稿，写图失败不产生指向缺失图的已保存正文。

**失败处理：** 只操作临时样本；保存或粘图失败时保留原文及现场，不能用 Base64 内联图片演示冒充独立附件方案通过。

**完成后：** T05，验证 HTML 与系统 PDF。

## T05 验证 HTML 与 PDF 最小导出

**依赖：** T04。**设计入口：** 技术设计 §9、§11。**覆盖：** R09、A09–A11、A14。**完成层级：** nativeVerified。

**输入：** 包含未保存修改、中文、表格、长代码、本地图片的原型文档。

**实施步骤：**

1. 捕获当前内容快照，生成净化的完整 HTML，内嵌本地样式和图片。
2. 准备正文专用打印页，等待字体和图片就绪，通过锁定 Tauri 的 macOS 打印入口打开系统对话框。
3. 实际保存 PDF 并检查分页/中文选择；搬移 HTML 后断网打开；区分对话框打开、取消与实际文件产物。

**产物：** 最小导出模块与打印样式；doc/evidence/T05-export-spike.md、脱敏 HTML/PDF 样本。

**完成条件：**

- 导出包含未保存的最新文字；HTML 离开原目录仍有本地图片，PDF 中文可选且长表格/代码不明显截断。
- 用户取消不显示保存成功；应用不将 print() 返回成功视为 PDF 已生成。

**失败处理：** PDF 不通过时先修打印页面/样式，记录 WebView 版本；不能换成整页截图 PDF 或跳过中文分页验收。

**完成后：** T06，判断这条技术路线是否放行。

## T06 冻结选型与通过技术验证门槛

**依赖：** T01、T02、T03、T04、T05。**设计入口：** 技术设计 §1、§12–14。**覆盖：** R01–R09、E06–E08。**完成层级：** nativeVerified。

**输入：** T01–T05 实际证据、原始失败样本与版本组合。

**实施步骤：**

1. 按相同样本汇总编辑、IME、往返、图片、三格式输出、权限与离线结果；逐项标 pass/fail/未验证。
2. 做初步体积/启动/内存测量，冻结首版版本、macOS/CPU 支持范围、语法矩阵、图片上限和性能验收口径。
3. 形成 GATE-1 决策；通过后将 POC 模块抽取路线写入设计；未通过时提出具体替代实验与影响任务。

**产物：** doc/evidence/T06-selection-gate.md；必要的产品/技术设计修订。

**完成条件：**

- GATE-1 只有在 T03–T05 的关键 macOS 证据通过且常见语法满足首版范围时才能 PASS。
- 已写明系统与依赖版本、PDF 系统对话框边界和全部性能冻结值；仍影响路线放行的待决项必须关闭，没有以文档能力宣称实测通过。

**失败处理：** GATE-1 失败即禁止推进 T07 的正式产品扩展；完成独立修复/定向验证，不自行切换完整技术路线。

**完成后：** PASS 后进入 T07；否则先关闭门槛中的失败项。

## T07 建立正式应用界面、会话和 IPC 契约

**依赖：** T06。**设计入口：** 技术设计 §2–5、§11。**覆盖：** R07、E01、E05。**完成层级：** automatedVerified。

**输入：** GATE-1 PASS、冻结版本；复用已验证原型能力。

**实施步骤：**

1. 实现空页面、标题栏、工具栏区域、可折叠侧栏和正文布局；提取共用样式 tokens。
2. 实现 DocumentSession/DocumentController、revision/generation 和类型化 IPC，定义错误/取消/事件契约。
3. 建立后端授权注册表与主窗口/打印窗口自定义命令权限隔离；移除可绕过服务的原型入口。

**产物：** src/app/、features/document/、core/contracts/、platform/；Rust services/security 与 capability/permissions。

**完成条件：**

- 会话状态能区分 dirty/saving/failed/conflict；旧 generation 回调不能更改当前文档。
- 界面组件和 IPC 契约检查通过；未授权窗口/伪造令牌被拒绝，打印窗口无通用文件命令。

**失败处理：** 服务未实现时使用显式 unavailable/mock 状态，只在组件检查环境使用替身，不能在正式应用中假显示保存成功。

**完成后：** T08，补全正式 Markdown 安全往返。

## T08 实现 Markdown Codec 与源码保护

**依赖：** T07、T02、T03。**设计入口：** 技术设计 §4、§6。**覆盖：** A03、A13、E02。**完成层级：** automatedVerified。

**输入：** 支持矩阵、T02 样本、正式 EditorAdapter 与 Session。

**实施步骤：**

1. 实现统一解析/序列化、front matter 原样保留、BOM/换行元信息及未知语法报告。
2. 可视化前执行兼容性检查和语义往返；失败则进入可编辑的源码保护模式，并保留原始文本。
3. 规范 mode 切换、未改 no-op、保存和导出能力开关；添加会导致源码丢失的回归反例。

**产物：** src/core/markdown/、源码编辑组件与 compatibility UI；doc/evidence/T08-codec.md。

**完成条件：**

- 支持样本的代码、链接目标、表格与列表语义保持，未修改文件不被自动整理；front matter 原始内容保持。
- 未知 HTML/脚注等不静默删除，保护模式可保存/导出 MD，HTML/PDF 限制有明确原因。

**失败处理：** 无法证明安全时默认源码保护并报告，不把所有常见文档退化为源码后算可视化需求通过。

**完成后：** T09，完成统一文件生命周期。

## T09 实现打开、新建和关闭保护

**依赖：** T07、T08。**设计入口：** 技术设计 §4–5、§7.1、§10。**覆盖：** R03、A02、A15、E01。**完成层级：** nativeVerified。

**输入：** DocumentController、Codec、原生对话框与授权注册表。

**实施步骤：**

1. 实现新建未命名、打开 .md/.markdown、读取 UTF-8 和文件元信息，显示标题与模式。
2. 统一打开/切换/关闭请求；未保存时提供保存/放弃/取消，保存接口尚未成功不能越过关闭保护。
3. 处理无权限、无效编码、超限、缺失文件、重复打开和取消；不为最近路径绕过授权。

**产物：** 文档菜单与操作协调器、open/save target token、读取服务；doc/evidence/T09-document-lifecycle.md。

**完成条件：**

- 原生对话框打开文件无需工作空间，默认可视化；取消/读取失败保留当前文档和选区。
- dirty 关闭三分支正确，保存失败保留窗口；无效 UTF-8 不被替换字符后覆盖保存。

**失败处理：** 不要先卸载当前编辑器再读新文件；错误需可重试且不改变旧 session。

**完成后：** T10，接入正式可靠保存。

## T10 实现原子保存和磁盘版本检查

**依赖：** T09。**设计入口：** 技术设计 §4.2、§5、§7.2。**覆盖：** A12、A15、E01。**完成层级：** automatedVerified。

**输入：** 保存目标令牌、DocumentSnapshot、DiskRevision、macOS 文件协调策略。

## T11 实现文件监听与冲突处理

**依赖：** T10。**设计入口：** 技术设计 §7.2–7.3。**覆盖：** A12、A15、E01。**完成层级：** nativeVerified。

# T11 / G11 外部变更与冲突代码阶段

日期：2026-11-07（Asia/Bangkok）。目标 `nativeVerified` 尚未达到。

## 实现

- 后端按当前授权文档的字节 hash 判断 `same/changed/deleted`；前端每 3 秒及回到前台时复查，保存前仍由 T10 再次核对。轮询结果携带文档 generation 和发起时磁盘版本，旧请求不会把自己的保存误判为外部冲突。
- 检出修改/删除后保留当前编辑器和 dirty 内容，显示冲突面板；可查看磁盘源码、显式放弃本地并重新加载，或通过系统对话框保留本地副本。副本写入新目标，复制原 `assets/` 并持久化当前待保存图片，不切换原会话。
- 自身成功保存会更新后端令牌与前端基线；非主窗口和伪造令牌仍被拒绝。

## 自动化

- `npm run test`：45 项 PASS，包含 dirty 冲突状态不丢内容。
- `cargo test --manifest-path src-tauri/Cargo.toml --lib`：7 项 PASS，新增真实临时文件的外部修改/删除检测。
- `npm run build`、`cargo check`：PASS。

## 未验证与限制

采用内容 hash 轮询与焦点复查，未接入 OS 事件 watcher；高频变更会合并为最终磁盘状态，保存前仍有二次复查。真实外部编辑器原子替换、中文/符号链接路径、副本图片完整性、监听时序仍需集中原生实测。非协作写入在最后 hash 检查后的剩余竞态见 T10。

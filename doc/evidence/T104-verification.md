## 计时的重测，以及它为什么不可比

`doc/evidence/T104-baseline-after.json` 是 T103 之后用 T91 的同一脚本取的。取数时本机的负载平均值在 23–78 之间（来自与本项目无关的其他进程），所有数值都被拉慢。两个没有被改动的函数可以当参照：

| 指标 | 改前（T91，机器空闲） | T104 重测（机器高负载） | 说明 |
| --- | ---: | ---: | --- |
| `rewriteImageUrls`，1 MiB + 20 图 | 375 ms | 1,148 ms | 函数未改，慢 3.1 倍，即当时机器的倍率 |
| `imageUrlsIn`，1 MiB + 20 图 | 350 ms | 1,074 ms | 同上，3.1 倍 |
| 2000 个 `$` 段落：之后各次序列化 | 140 ms | 22 ms | 按 3.1 倍折算约 7 ms；T92 在空闲时量得 10 ms |
| 2000 处公式问题的 `analyzeMarkdown` | 559 ms | 843 ms | 按 3.1 倍折算约 270 ms；T92 在空闲时量得 250 ms |
| `findInText`，1 MiB 单字 | 1 ms | 3 ms | 未改 |

所以计时项的结论以各任务在机器空闲时量得的数值为准（记录在各自的证据文件里），本表的重测只说明方向一致。Rust 的两项计时同样受负载影响：空闲时 SHA-256 64 MiB 为 25 ms（改前 118 ms），UTF-8 解码 20 MiB 为 18 ms（未改）。**如需一组干净的改后数值，请在机器空闲时重跑 T91 证据里的三条命令。**

## 需要用户知道的事

1. **本批没有任何实机验证。** 上表的 PENDING 都要在 `src-tauri/target/release/bundle/macos/Mino.app` 里确认，清单见[验收与发布 §8I](../05-验收与发布.md)。其中风险最高的三处是：PDF 缩放时保留旧画面的实际观感（T97）、纹理与字体改为从文件加载后在打包应用里的显示和导出（T98）、原生菜单与启动顺序（T99）。
2. **`read_app_asset` 的允许范围扩大了**：为了让导出能内嵌纹理，除 `.woff2` 外允许读取四种纸张的纹理 PNG（T98）。CSP 与 capabilities 未改。若不接受，可改为把纹理另行内联进导出代码块，应用体积增加约 1 MiB。
3. **备份清理会删文件**：每个文档下次保存后，旁边更早的 `.mino-backup-*.bak` 只留最新 1 份（2026-11-12 用户决定，原为 3 份）；应用数据目录里的 296 个旧备份会在各记录文件下次写入时清到每个 1 份（T101）。
4. **默认字号统一为 15**：与 Rust 默认值和“重置缩放”一致。若本意是 16，需要一并改 Rust 与测试（T102）。
5. **四个未被调用的命令已删除**（T103）。
6. **新增依赖**：`sha2 0.11.1` 及其 6 个依赖（MIT OR Apache-2.0），已记入 `rust-dependency-licenses.tsv`。`./build.sh` 通过；打包用的许可文本合集是否已包含这 7 个包没有单独核对，npm 侧的两份许可清单此前就已过期（T90 时记录），本批未处理。
7. **计时的改后数值是在高负载下取的**，结论以各任务空闲时的测量为准；需要干净数值请在空闲时重跑。
8. 方案 §5“未列入本批”的候选（三款整包中文字体切片、草稿的 `F_FULLFSYNC`、非 macOS 回退分支、PDF 标签保活等）没有做。另有两处在执行中核对后留下的：`styles.css` 里约 40 行先声明后覆盖的规则（没有视觉比对手段）、Rust 的有界读取与菜单两张表。

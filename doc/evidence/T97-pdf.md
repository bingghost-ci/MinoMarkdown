## 逐项结果

| 编号 | 改前 | 改后 | 结论 |
| --- | --- | --- | --- |
| P6-1 重画时白屏 | 缩放一变就先清空页面再开始绘制；适应宽度时宽度每变一次立即重排并重画 | 已有画面的页面在新尺寸绘制完成前保留旧画布（由 CSS 拉伸），完成后一次换上新画布、文字层和链接层，旧画布随即清零；首次绘制仍立即挂上画布。适应宽度的计算在宽度停止变化 120 ms 后才执行 | 达标，保留 |
| P6-2 页面清理 | `release` 不调用 `cleanup()`，滚动过的页的解码数据一直保留 | 页面离开屏幕附近时取消绘制并调用该页的 `cleanup()`；卸载时全部清理 | 达标，保留 |
| P6-3 页面列表 | 翻页、输入页码都会重渲染全部页面框并拆装全部 ref | 页面框拆为 `memo` 子组件 `PdfPages`，只在尺寸或缩放变化时渲染 | 达标，保留 |
| P6-4 控制条模糊 | `backdrop-filter: blur(10px)` 垫在 92% 不透明的背景后面 | 删除模糊，背景改为不透明（控制条整体的 `opacity: 0.94` 未动） | 保留（代码审阅） |

重画期间的细节：旧的链接层按旧尺寸的像素定位，所以立即移除，新链接层随新画布一起出现；文字层按 CSS 变量缩放，保留到替换为止。查找高亮在该页重画完成后重新绘制。

每个 PDF 使用自己的 worker（T86 的修复）、`useWasm: false`、不使用 `fetch` 均未改动，`pdfEngine.ts` 只改了一处引用路径（T94）。

## 测试

新增 `tests/pdf-view.test.ts`（4 项）：

- 第 1 页可见时绘制第 1、2 页；第 3 页可见、第 1 页离开后，第 1 页被清空并调用 `cleanup()`，第 2 页保留；卸载后三页都被清理。
- 面板变窄后重新绘制：新绘制完成之前页面上仍是原来的画布、尺寸未被清零；完成后换成更小的新画布，旧画布清零，页面里只有一个画布。
- 连续 10 次宽度变化期间缩放不变、绘制 0 次；停止 120 ms 后重排，附近的页各绘制 1 次，且都是最终宽度的缩放。
- 在页码框里逐字输入（每次都渲染视图）：页面框的 ref 注册 0 次，DOM 节点不变。

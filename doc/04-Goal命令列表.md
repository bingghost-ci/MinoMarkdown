# MinoMarkdown Goal 命令列表

版本：v0.1 · 日期：2026-11-06 · 上游：[分步开发计划](03-开发计划.md)。

## 使用方式

G01–G29 分别对应 T01–T29，每项命令可独立复制到支持 Goals 的 Codex 会话中。开发阶段按代码依赖顺序执行；前项的原生测试或人工验收待补时，记录后继续开发下一项。命令不是终端 Shell 指令。

当前代码与证据以[开发进度](06-开发进度.md)及实际文件为准，不根据旧 Goal 的状态重复开发。没有预设 token/时间预算，也不创建其他任务执行器。单项命令与末尾的连续开发总 Goal 是两种执行入口；总 Goal 在同一目标内逐项推进。

官方命令形式为 `/goal <目标>`；可用 `/goal` 查看、`/goal pause` 暂停、`/goal resume` 继续、`/goal clear` 清除。界面需支持该功能；这些是官方语法说明，不证明当前客户端版本或账户已实际验证。[OpenAI：Using Goals in Codex](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)。

## 通用执行约束

- 先读原始需求、产品方案、技术设计、对应任务章节和唯一进度表，再确认当前源码与证据。已有合格实现应复用，不能重建或覆盖用户变更。
- 只做本项任务及满足本项必需的修复；开发阶段以代码、配置、文档和可独立完成的检查为准，开发计划与验收文档中的原生完成条件留待集中测试。先定位可直接修复的原因再修；同一检查最多执行 3 次（首次加至多 2 次复查），仍失败就保留命令、输出、影响和下一步，继续不依赖该检查的开发。不得为通过而缩减样本。
- 只在项目和专用临时样本内开发与检查，不修改用户真实文档；依赖按实际来源锁定，不随意升级整套框架。
- 允许在该任务被用户执行后进行必要的本地构建/检查；当前会话若明确要求不运行，则只写代码，保留未运行状态与 gate。
- 每次更新 doc/06-开发进度.md。分别说明代码、自动化、原生实机和用户验收；原生条件缺少时不得用 mock 冒充通过。
- 不自动对外发布、上传产物、创建远程仓库或推送；后续用户明确要求提交时，再按全局约定 commit + push。
- 开发阶段的原生测试、用户操作、性能或签名缺席只记 PENDING，不作为后续代码任务的停机条件。只有缺少实现所必需的输入、无法安全继续任何代码工作时，才说明真正的开发阻塞。已发现的严重数据风险先隔离受影响功能并记录，不隐瞒风险或伪造通过。

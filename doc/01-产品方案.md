# Mino 产品方案

版本：v0.1 · 日期：2026-11-06 · 输入：[原始需求](../Markdown编辑器.md)。

## 1. 产品定位

Mino 是以本地文件为中心的轻量桌面 Markdown 编辑器。用户打开文件或文件夹后直接编辑排版后的正文，可以输入简单 Markdown 语法，也可以点击工具栏；截图粘贴后能够随文档长期保存，并可输出 Markdown、HTML、PDF。

“接近飞书”落实为正文直接编辑、选区操作稳定、格式易发现、图片插入自然。首版不引入账户、云端服务或多人协作。

2026-11-11 定位修订（T70–T73，见 §3.9）：Mino 由“本地离线”改为**默认离线，AI 为用户主动开启的可选联网功能**。不开启 AI 时应用行为与以前完全一样，不发出任何网络请求；webview 仍然没有任何网络权限，CSP 不变，只有 Rust 进程在用户开启 AI 并同意后向用户配置的地址发请求。仍不引入账户、同步和多人协作；本文及其他文档中“离线”“不联网”的表述均按这一口径理解。

优先服务三种日常场景：单篇记录快速写作、已有 Markdown 目录维护、含截图的文档整理与分享。

## 2. 方案默认选择

以下是为形成可执行计划采用的默认建议。后续用户提出不同选择时，按影响范围调整，不把建议追认为原始需求。

| 编号 | 默认方案 | 原因与变更影响 |
| --- | --- | --- |
| D01 | 首版只交付 macOS；优先当前开发机架构 | 先把系统 WebView、中文输入、粘贴与打印验证完整；Windows/Linux 另立适配计划 |
| D02 | 自建桌面外壳，优先 Tauri 2 + Milkdown/Crepe | 文件和导出逻辑可独立维护；不直接改造完整开源应用。T06 前保留更换编辑器适配器的余地 |
| D03 | 顶部常驻工具栏，选中浮动栏可关闭 | 满足格式操作易发现；即使所锁 Crepe 版本无可用 TopBar，也由应用工具栏调用适配器 |
| D04 | 默认可视化，链接通过小面板修改 | 日常写作少暴露源码；无法可靠往返的文件进入明确标识的源码保护模式 |
| D05 | PDF 采用系统打印对话框中的“存储为 PDF” | 首版提供可验证的 macOS 路径；界面写“打印 / 保存为 PDF”，不承诺一键生成和可检测的保存完成 |
| D06 | 标准 Markdown + 常用 GFM；不编辑数学、Mermaid、脚注、任意 HTML | 保证首版可控；这些内容保留源码，不静默删除。围栏语言为 mermaid 时按普通代码块保存 |
| D07 | 图片放在文档旁 `assets/`，引用相对路径 | 文档可迁移，不依赖图床与应用数据库；另存和 MD 导出负责复制资源 |
| D08 | 编辑时手动保存；关闭窗口或退出时自动保存已绑定磁盘的修改 | 退出前遵守磁盘版本检查；保存失败时不关闭。未命名文档由用户决定保存、放弃或取消 |
| D09 | 多窗口、每窗口多文档 Tab | 打开和新建保留本窗口已有文档；Tab 可移到新窗口；逐个关闭未保存 Tab 时处理保存、放弃或取消 |

macOS 最低版本、支持的 CPU 架构和可发布签名方式在 T06/T28 的实际环境验证后记录，不在方案阶段编造兼容结论。

## 3. 首版范围

### 3.1 必须交付

| 领域 | 功能范围 | 不通过的例子 |
| --- | --- | --- |
| 打开 | 单文件、目录浏览、未命名新文档 | 强制创建工作空间才能打开文件 |
| 编辑 | 段落、H1–H6、加粗、斜体、删除线、列表、任务列表、引用、代码、链接、图片、简单表格、分割线 | 默认只显示源码或只能预览 |
| 输入 | 原需求中的 Markdown 快捷转换、转义、撤销/重做、中文组合输入保护 | 中文候选上屏时吞字或重复转换 |
| 工具栏 | 格式状态、原选区应用、插入、历史、保存与导出 | 点击按钮丢失选区或把格式加到错误位置 |
| 文件可靠性 | 手动保存、另存、保存状态、关闭保护、外部修改提示、崩溃恢复 | 写入失败显示“已保存”，或把外部修改静默覆盖 |
| 图片 | 粘贴截图、文件选择/拖入、替代文本、删除/替换、首次保存迁移 | 重开后图片消失，或最终 Markdown 留下临时 URL |
| 输出 | MD 与附件、自包含本地 HTML、系统打印到 PDF | 仅导出磁盘旧内容、HTML 依赖应用内部协议 |
| 离线与安全 | 本地资源离线可用、文档脚本不执行、文件访问限定于打开范围 | 文档内脚本可以调用文件写入或自动读取任意文件 |

### 3.2 首版配套建议

目录内新建文档/子目录、文件重命名、移到废纸篓、最近打开、macOS 文件关联/拖入文件、浅深主题与系统跟随、基础设置与键盘操作。它们是本方案纳入的配套能力，不作为已被用户单独确认的需求。

目录结构移动会影响其他文件的相对链接。首版不承诺全目录引用自动修复；有风险时解释影响并要求通过可审阅的“另存为”复制资源。重命名与废纸篓操作限定为明确选择的条目。

### 3.3 后续范围

编辑过程中的持续自动保存原文件、全文搜索/替换、大纲、图床、图片裁剪/自由布局、公式渲染、Mermaid 渲染、脚注可视化、Windows/Linux、同步、协作、AI、插件。首版 Goal 不包含这些功能。

其中 AI 已由 2026-11-11 的 T70–T73 纳入范围，边界见 §3.9；同步、协作、插件仍不在范围内。

### 3.4 首版后增强（T35–T41）

2026-11-10 用户要求为以下增强建立 Goal。其余后续范围不变。D06、D08 描述 T34 及之前的行为，对应任务完成后以本节为准。

| 任务 | 功能 | 产品边界 |
| --- | --- | --- |
| T35 | 源码保护文档导出 HTML/PDF | 输出净化后的内容；有内容未输出时明确提示 |
| T36 | 文档大纲 | 右侧面板，默认收起，点击跳转 |
| T37 | 数学公式可视化 | 行内和块级公式可编辑并保持原文；无法安全往返时仍退回源码保护 |
| T38 | Mermaid 图形渲染 | 只显示图形，源码仍保存为普通 `mermaid` 代码块；不支持图形化编辑 |
| T39 | 定时自动保存 | 设置项，默认关闭，只作用于已绑定磁盘的文档；关闭时沿用 D08 |
| T40 | 文件夹全文搜索 | 只搜索当前工作区的 Markdown，无持久索引，不做跨文件替换 |
| T41 | 恢复上次会话、字数统计 | 恢复为设置项，默认关闭，保持用户要求的启动即空白编辑；字数显示在状态栏 |

### 3.5 编辑能力增强（T42–T48）

2026-11-10 用户认为文本编辑功能单一，要求增强编辑能力，并提出文本缩放和加宽居中正文。本批不新增 Markdown 语法，`==高亮==`、上下标、下划线和文字颜色不在范围内。T42 完成后，居中宽度以本节为准，[界面重设计](07-界面重设计.md)中的 860px 是历史记录。

| 任务 | 功能 | 产品边界 |
| --- | --- | --- |
| T42 | 文本缩放、加宽居中正文 | `Cmd+=`、`Cmd+-`、`Cmd+0` 调整正文字号，与设置中的字号是同一个值；居中容器从 860px 加宽到 1040px，宽屏模式和导出不变 |
| T43 | 编辑入口与快捷键 | 原生“格式”菜单列出常用命令和快捷键，`Cmd+K` 插入链接，工具栏增加任务列表和列表缩进 |
| T44 | 段落移动与复制 | `Option+↑/↓` 移动当前块，`Cmd+Shift+D` 复制当前块，各为一步撤销 |
| T45 | 查找增强 | 区分大小写、全词匹配、正则；可视化和源码保护模式行为一致；只在单个文本块内匹配 |
| T46 | 智能粘贴 | 选中文字后粘贴单个安全网址变成链接；粘贴规则的制表符文本变成表格；代码块内始终按原文粘贴 |
| T47 | 选中文本转换 | 英文大小写、中英文之间加空格、全角半角标点互转；只作用于选区，且由用户主动触发 |
| T48 | 源码编辑器升级 | 源码保护模式改用 CodeMirror，提供行号、Markdown 高亮和 Tab 缩进；保存内容与编辑内容逐字节一致 |

### 3.6 阅读体验：页面视图与护眼主题（T49–T50）

2026-11-11 用户认为居中显示不好用，希望像 Word 那样看到页面边界；认为水墨屏不像水墨屏，要求检查全部主题并提供护眼模式，并明确本工具主要作为 Markdown 文档阅读器使用。本批只改变显示，不改变文档内容、设置字段和 HTML/PDF 导出样式。主题名称与配色以本节为准，[界面重设计](07-界面重设计.md)中的主题描述是历史记录。

| 任务 | 功能 | 产品边界 |
| --- | --- | --- |
| T49 | 页面视图 | 原“居中”改名“页面”：正文放在带边界和阴影的纸张上，纸张外是较暗的桌面色，纸张两侧至少保留桌面边距；宽度沿用 1040px，宽屏和源码编辑器不变 |
| T50 | 主题修订与护眼模式 | 淡绿色改为护眼绿（豆沙绿纸面），淡黄色改为护眼黄（羊皮纸），石墨改为夜间护眼（暖色低蓝光深色），水墨屏改为浅灰白纸面、墨色文字、无彩色；暖纸、护眼绿、护眼黄、水墨屏的纸面带细颗粒与纤维纹理，浅色和科技蓝白保持无纹理；行内代码随主题取色；主题 ID 不变，已保存的设置继续有效 |

### 3.7 阅读体验重塑（T51–T60）

2026-11-11 用户认为 T50 的纸张纹理看起来脏，要求提供牛皮纸、羊皮卷、宣纸等多种纸张风格和护眼风格，并明确 Mino 主打阅读：先把阅读体验做好，字体、Markdown 展示、HTML/PDF 导出和图片都要带上统一风格。目标、原则、风格目录与计划见[阅读体验章程](08-阅读体验章程.md)，本节只列边界。

| 任务 | 功能 | 产品边界 |
| --- | --- | --- |
| T51 | 风格基础重构 | 风格成为数据，编辑器、预览、导出共用；旧主题 ID 继续有效 |
| T52 | PDF 打印背景验证 | 在 macOS 27 上只做技术验证与结论，不改用户可见行为；风险见根目录 README |
| T53 | 纸张材质库 | 书页、宣纸、牛皮纸、羊皮卷、再生纸、暖黄的纹理；离线生成、干净无污渍；素白无纹理 |
| T54 | 护眼与夜间风格 | 豆沙绿、暖黄、水墨屏、低蓝光、夜读、深色、墨黑；跟随系统时日夜配对 |
| T55 | 字体与排版 | 随包思源宋体与霞鹜文楷（OFL，各 400/700）；字体预设、段距、行宽、对齐、首行缩进、中文标点；只影响显示 |
| T56 | Markdown 元素呈现 | 标题、列表、引用、代码、表格、分隔线、链接、公式、图表随风格 |
| T57 | 图片呈现 | 衬边、图注（只渲染不改文档）、夜间降亮、放大查看 |
| T58 | 阅读模式 | 打开文件默认进入（新建、草稿恢复、有未保存修改的除外，可在设置关闭）；只读、隐藏编辑控件、翻页、记住阅读位置 |
| T59 | 导出套用风格 | HTML 与 PDF 可选当前风格或简洁白底；HTML 只内嵌用到的字体分片；PDF 有与屏幕一致和打印友好两种模式 |
| T60 | 风格画廊与整体验收 | 设置页按纸张、护眼、夜间分组；四个出口观感一致 |

2026-11-11 用户确认：环境为 macOS 27，技术风险写入根目录 README；随包开源中文字体；打开文件默认阅读模式；首批风格名单按章程。本节取代 §3.5 中“HTML/PDF 导出字体仍固定”的约束，以及 §3.6 中 T50 的纹理做法。

2026-11-11 实现后调整（章程 v0.3 §16）：PDF 默认打印友好，“与屏幕一致”只在打印区域内铺纸色，页边距为白色，因为 WebKit 无法同时满版和保留每页页边距；霞鹜文楷没有分片，HTML 导出改用系统楷体，打印仍用随包字体；编辑器中图注只显示图片标题。

2026-11-11 收尾：代码语法高亮扩展到预览与导出；设置新增表格样式（三线表 / 全框线），未写对齐的数字列显示时右对齐；切换风格时 Mermaid 图随之重绘；`tauri dev` 下导出也内嵌字体。均只改呈现，不改 Markdown。富内容超长文用随包书宋滚动时布局较慢，列为待实测风险。

### 3.8 阅读外观重做与字体扩充（T61–T69）

2026-11-11 用户审阅 T51–T60 的结果后，对现有全部 14 种风格不满意（“都很丑”），以微信读书网页版为参照：中性灰画布上一张干净的大圆角纸面，颜色只用在标题上，右侧一列悬浮圆形按钮，弹出式字体面板（字号滑杆加用各自字体渲染的字体网格），浅色与深色两套。用户要求纸张、羊皮卷风格“要有纹路，要有质地感”，字体要更多，并同时照顾中文和英文文档。

对 T51–T60 结果的诊断：五种米黄色风格彼此分不开；界面（侧栏、工具栏、画布）跟着纸面染色，整屏一片黄或绿；256px 程序噪点纹理没有纤维、帘纹和纸边，认不出纸种；纸面直角、弱阴影；字体只有 4 个预设，西文只有 Georgia / SF 兜底。

用户确认的决定：

- 风格精简到 9 种并重做，不在 14 种上微调。
- 字体采用“随包少量开源字体 + 读取系统已装字体”。商业字体（方正、仓耳、汉仪等）一律不随包，用户自行安装后可在“本机字体”中选用。

风格目录、色值、材质与字体方案见[阅读体验章程](08-阅读体验章程.md) v0.4，本节只列边界。

| 任务 | 功能 | 产品边界 |
| --- | --- | --- |
| T61 | 配色体系重定 | 画布为不随纸面染色的中性灰（浅色风格约 `#f2f3f5`，深色约 `#1c1c1e`）；界面色（侧栏、工具栏、状态栏）只有浅、深两套中性色，只有强调色随风格；纸面为大圆角卡片（圆角 14px、柔和阴影、更大的页边距）；一、二级标题用风格的强调色，正文用柔和深灰（浅色）或浅灰（深色）；对比度沿用章程（正文 ≥ 7:1，次要文字、链接与标题 ≥ 4.5:1） |
| T62 | 风格精简为 9 种 | 白、灰白、书页、宣纸、羊皮卷、牛皮纸、豆沙绿、深色、纯黑；旧风格 ID 在读取设置时按映射表迁移，不得因旧 ID 回退到默认设置（T74 起为 12 种，纯黑已移除，见 §3.10） |
| T63 | 纸张材质重做 | 书页、宣纸、羊皮卷、牛皮纸按纸种分别制作，能认出纸种且保持干净；新增“纹理强度”设置（0–100，默认 60）；不影响正文对比度与滚动性能；其余 5 种风格无纹理 |
| T64 | 界面外观 | 编辑区右侧一列悬浮圆形按钮（目录、字体与风格面板、AI（仅启用后出现）、日夜切换、阅读/编辑切换）；工具栏、标签栏、侧栏去掉重边框并弱化；阅读模式只留纸面，隐藏工具栏和状态栏，靠悬浮按钮和快捷键操作 |
| T65 | 风格与字体弹出面板 | 字号滑杆、风格色块、纹理强度滑杆、字体网格（每个按钮用自身字体渲染，分“中文 / 西文 / 本机”三组，本机字体可搜索）、行距；设置页里的外观与排版页改用同一套组件 |
| T66 | 随包开源中文字体扩充 | 候选：思源黑体、霞鹜新晰黑、朱雀仿宋、寒蝉活宋、汇文明朝体、京华老宋体；只收录授权明确允许随应用再分发、转换为 WOFF2 并嵌入导出 HTML 的字体，名单以 T66 证据为准 |
| T67 | 读取系统已装字体 | 只读取字体族名列表，不读取字体文件，不上传；选中的本机字体只影响显示，不写入文档 |
| T68 | 西文字体与中西搭配 | 随包 Source Serif 4、Literata、EB Garamond、Inter、JetBrains Mono（均 OFL，仅 latin / latin-ext 子集）；中文字体与西文字体分开选择；以西文为主的文档自动使用西文排版，可在设置中关闭 |
| T69 | 体积与性能 | 应用体积预算 ≤ 80 MiB（现为 36.82 MiB），记录每类字体的实际增量；查明并修复 T55 证据中随包书宋在富内容长文上滚动布局慢的问题 |

### 3.9 AI 分析（T70–T73）

2026-11-11 用户希望集成 ChatGPT 或 DeepSeek 的 API，做类似“AI 问书”的文档分析；用户自己持有这两家的 API 密钥。用户确认：AI 为默认关闭的可选功能，产品定位改为“默认离线，AI 为用户主动开启的可选联网功能”（见 §1）。

边界说明：

- **不开启 AI 时应用行为与以前完全一样。** 不发出任何网络请求，不出现 AI 按钮和面板，不访问钥匙串。
- **webview 仍然没有任何网络权限，CSP 不变。** 只有 Rust 进程在用户开启 AI 并同意后，向用户配置的地址发请求；除该地址外不联系任何其他服务，Mino 自身没有服务器，不做统计或遥测。
- **发送什么由用户触发决定。** 只有用户在面板中发起的操作才发送内容，范围是当前文档正文或选中的文字；不发送其他文件、目录结构、本机路径或图片文件。没有后台自动分析。
- **AI 不直接修改文档。** 只有 T72 中用户明确选择“替换”或“插入”时才产生编辑，且可撤销；AI 的回答不执行脚本，不触发文件操作。
- **费用与服务条款由用户与服务商之间负责。** Mino 不提供密钥，不代收费用。
- 不做：账户、云端会话同步、对话历史上传、多文档知识库与向量索引、图片理解、联网搜索、让 AI 调用本机命令。这些需另立任务。

本节取代的既有表述：§3.1 “离线与安全”行、§3.3 把 AI 列为后续范围、[技术设计](02-技术设计.md) §11 “不启用任意 HTTP 或远程 API 能力”、[开发计划](03-开发计划.md)“不在本计划中创建 AI”，均按 §1 的新定位修订；这些表述对未开启 AI 的应用仍然成立。

## 5. 关键用户流程

### 5.1 打开并编辑文件

打开文件 → 读取与兼容性检查 → 可视化编辑或源码保护模式 → 修改后显示未保存 → Cmd+S → 成功显示已保存。

打开未修改的文件不会因为编辑器初始化就自动重写。文件编码无法安全解码时保留原文件并说明；首版直接编辑 UTF-8（含 BOM），不自动转换未知编码。

### 5.2 新建、粘图与首次保存

新建未命名文档 → 粘贴截图并在光标处显示 → 自动保存可恢复草稿和临时附件 → Cmd+S 选择 `.md` 目标 → 先复制图片并生成最终引用 → 原子提交正文 → 更新会话。

用户取消保存时继续保留草稿。图片写入失败时正文不引用不存在的最终文件，界面显示可重试状态。删除图片节点不删除共享磁盘资源。

### 5.3 目录操作

打开文件夹 → 按需加载目录树 → 选择文档 → 在新 Tab 打开并保留已有文档。关闭窗口或退出时，已绑定磁盘且有修改的文档先按原版本校验并保存；未命名且有修改的文档询问保存、放弃或取消。保存失败、冲突或取消时保留窗口。文件夹中的非文档资源默认不铺满导航；忽略 `.git`、构建缓存及隐藏目录，允许后续设置调整。

拖动 Tab 调整本窗口顺序；拖出窗口边缘或使用 Tab 右键菜单，将它移到独立窗口。新窗口保持空白启动状态，不自动装载上次会话。需要恢复未保存草稿时使用“文件 > 恢复草稿…”，不在窗口顶部自动插入提示。

重命名正在编辑的文件时更新会话路径与监听；跨目录另存通过资源迁移流程完成。非空目录的递归重命名/删除暂不提供，避免首版引入隐含的大范围修改。

### 5.4 外部修改与关闭

干净文档被外部修改：提示可重新加载，保留阅读位置；已修改文档被外部修改：进入冲突状态，保留编辑快照，可查看磁盘版本、另存本地副本、重新加载。关闭未保存文档给出保存、放弃、取消，保存失败不能继续假装关闭成功。

### 5.5 导出

点击导出 → 固定当前编辑快照 → 等待该快照关联的图片处理完成 → 选择格式与位置 → 生成产物或进入打印对话框。

- MD：默认导出文档与资源目录；另存为会切换活动文件，导出不会。
- HTML：默认内嵌已解析的本地图片与样式，搬到另一目录依然能打开。
- PDF：准备只含正文的打印预览，打开系统对话框，由用户选择“存储为 PDF”。应用只提示“已打开打印对话框”；不能据此宣告 PDF 已保存。

导出期间继续编辑不会改变已捕获快照。无效本地图片需先修复，或由用户明确选择带占位符的输出；网络图片默认不下载，必须说明输出是否仍依赖网络。

## 6. 新增工程要求

| E02 | 兼容性检查与源码保护模式 | 防止未知 Markdown 被可视化往返删除 |
| E03 | 图片写入、迁移、异步插入统一管理 | 保证首次保存、撤销、另存与导出的资源一致 |
| E04 | 导出固定当前快照 | 保证未保存内容与并发编辑的输出可解释 |

| E06 | 依赖锁定、离线资源、许可证清单 | 形成可重复构建和可交接产物 |
| E07 | 轻量指标以固定环境和样本测量 | 不把框架宣传当成产品性能 |
| E08 | 源码、自动化、实机和用户验收分别记录 | 能明确判断开发完成到哪一层 |

## 8. 风险与退出策略

| 风险 | 早期验证 | 失败时的处理 |
| --- | --- | --- |
| WebView 中文输入/选区不稳定 | T03 使用系统中文输入法连续写作 | 优先调整编辑适配器；必要时定向验证 Vditor，不能带着吞字问题扩展目录功能 |
| Markdown 往返损失内容 | T02/T03 对比语义与原文保留 | 源码保护；若常见语法也失败，T06 不放行 |
| 图片粘贴或路径失效 | T04 真截图、中文路径、首次保存 | 调整原生剪贴板与资源服务；不能仅用网络图片演示代替 |
| PDF 字体与分页异常 | T05 真正打印并查看 PDF | 调整打印样式与平台桥接；若仍失败，记录并重新设计 PDF 路径 |
| Tauri 方案达不到产品要求 | T06 集中评审实测证据 | 提出明确替代方案及影响任务；未获新的路线决定前不自动迁移成 Electron 或改造 MarkText |
| 缺少对外签名身份 | T28 区分本地包和分发包 | 可交付本地验证产物；对外发布状态保留未完成 |

不在规划阶段承诺固定体积、内存、开发天数或跨平台效果。T06 冻结可测量目标，T27 对同环境复测并说明差异。
